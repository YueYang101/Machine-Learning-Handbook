0. 先纠正一个术语：PPO 不是完整“backbone”

PPO 主要规定如何用 on-policy rollout 更新 actor / critic。它不规定 actor 必须是 MLP、Gaussian、GRU、MoE 或 diffusion，也不自动决定 observation、grasp goal、课程、teacher/student 和安全层。

多数灵巧抓取失败，不能只通过“换一个 PPO 变体”解释。

真正属于 PPO update 的核心问题主要是 on-policy 数据复用和 clipping / trust-region；多模态、隐藏动力学、多任务冲突、sim-to-real、安全和长尾，分属不同层级。

本页的判别顺序

先看症状和反事实实验，再定位层级；同一个现象可能需要的是 goal condition、GRU、数据重采样或硬安全层，而不是修改 PPO surrogate。

分类标签：只有 U / O 真正触及 PPO update 或优化目标

阅读论文时最常见的归因错误 “PPO + GRU + privileged critic + curriculum + domain randomization + distillation”取得提升，不代表 PPO objective 被证明更好；必须通过逐层消融，判断收益来自 optimizer、representation、data distribution 还是 deployment wrapper。
三个容易混淆但必须分开的概念 Goal-conditioned PPO ≠ HER：前者只是 π(a|o,g), V(o,g)；原始 HER 是 off-policy replay 技术。Asymmetric critic ≠ privileged teacher：前者同一次 PPO 中 actor 看部署观测、critic 看 full state；后者是先训 teacher 再蒸馏 student 的两阶段 pipeline。RMA ≠ recurrent PPO：RMA 通常先训 privileged latent-conditioned base policy，再监督训练 history adapter；GRU-PPO 则直接通过 recurrent policy gradient 学 history state。

1. PPO 能不能支持多个对象、多个物理分布、多个抓姿？

能，但“支持”不等于“一个共享网络会自动学好”。这里至少有三种不同的 distribution。

分布PPO 是否原生可训练真正的瓶颈最小辨别实验
环境分布
p(object, μ, mass, COM, wrist)		可以。每回合从混合环境采样即可，不必改 PPO objective。观测是否足以区分、采样是否平衡、共享 capacity、平均 return 是否牺牲长尾。universal policy vs 同总预算 specialists；macro / worst-group，而非只看 micro mean。
任务 / 意图分布
p(mode | object, intent)		可以，但应给 mode / goal / affordance condition。同一个“瓶子”在递水、喝水、倒水时最优接触不同；没有 condition 时标签本身一对多。无 condition vs goal token；比较 mode accuracy、稳定性和 cluster coverage。
动作分布
π(a | s, g)		PPO 数学不要求 Gaussian；只要能评估采样动作的 log-prob / ratio。常用 diagonal Gaussian 是单峰且无手指 covariance，可能平均化或 mode collapse。goal-conditioned Gaussian vs GMM / latent / generative policy，同状态动作聚类与闭环成功。
J(θ) = E_{τ ~ p(task,physics), πθ}[R(τ)] 一个 shared PPO 默认优化混合分布的平均回报； 这不保证每个 object family、wrist pattern 或最差 10% 都非劣。

先 condition，再谈多峰 actor

若“喝水/递水”已经由 g 区分，原本多峰的 π(a|s) 可能变成较简单的 π(a|s,g)。这通常比直接上 diffusion 更可解释。

多个对象不是多个模型

PPO 可以训练 universal policy；是否需要 experts / MoE 取决于 shared policy 与 specialists 的 gap、gradient conflict 和容量，而不是对象数量本身。

未知参数需要 history

若 μ、质量、COM 或液体相位不可观测，增加 object randomization 只会暴露 POMDP；更大 MLP 不能解除 observation aliasing。

2. 十类局限：机制、症状与研究方向

这张表是定位地图，不是改模清单。只有出现对应症状，相关方向才进入下一轮候选。

# / 局限机制可观测症状论文中常加什么代价 / 新风险
1 · On-policy 样本效率
U		 rollout 必须来自当前/近当前 policy；同 batch 可多 epoch，但旧经验长期复用会产生偏差和 ratio 方差。 success-vs-transitions 上升很慢；稀有成功只出现一次；减少并行环境就明显退化。 PPG、GePPO、受控近期 replay；demo pretrain、teacher distillation；SAC / offline RL 作为非 PPO 对照。 off-policy bias、importance-weight variance、更多 buffer / hyperparameters；替代算法有 Q 偏差。
2 · Clip / trust region
U		 clipped surrogate 只截 sampled-action ratio 对 objective 的贡献，不是整个 policy KL 的硬约束。 KL 突刺、clip fraction 过高、ratio heavy tail、entropy/std 突降、一次 update 后 evaluation cliff、seed 方差大。 target-KL early stop、adaptive KL penalty、Truly PPO rollback、TRGPPO；TRPO 作严格 trust-region 对照。 更新更保守可能变慢；rollback / KL target 增加超参；TRPO 二阶计算更复杂。
3 · 单峰动作表达
A		 常见 diagonal Gaussian 同一 condition 只有一个连续 mode，且忽略手指动作 covariance；这不是 PPO 定理限制。 只剩一种抓姿；平均出无效中间动作；expert 聚类多峰而 actor 只覆盖一簇；逐时 latent 切换导致抖动。 goal / episode-latent condition、full / low-rank covariance、autoregressive、GMM / MoE、flow、DPPO。 likelihood 与 ratio 更难估；router/component collapse；生成策略多步采样带来延迟。
4 · 多任务负迁移
A / P		 共享 trunk / critic 优化 task mixture 的平均 return；异质任务 reward scale 和梯度可能冲突。 增加对象后旧对象退化；per-category 曲线交替涨跌；specialists 明显高于 universal；gradient cosine 常为负。 task / object condition、balanced sampler、per-task critic/head、PCGrad、soft modularization / MoE、experts→distillation。 task descriptor 可能部署不可得；专家和路由扩容；distillation 丢尾部技能；per-task gradient 计算贵。
5 · POMDP / 隐藏动力学
A / P		 摩擦、质量、COM、液体状态、接触和 sensor latency 不可见时，相同瞬时 observation 可能要求不同 action。 privileged oracle gap 大；参数中途切换就失败；history / GRU 显著优于 MLP；接触数帧后才会正确反应。 frame stack、recurrent PPO、asymmetric critic、RMA / history adaptation、belief latent、显式 observer。 sequence buffer、BPTT 和 hidden reset 复杂；更多延迟/显存；latent 未必可辨识。
6 · 探索 / reward shortcut
P		 高维接触成功序列稀疏；局部 Gaussian entropy 难跨行为 basin，dense shaping 又可能诱导 simulator exploit。 大多数 seed 永远零成功；只用一两根手指；contact reward 高但 lift=0；策略借桌面/碰撞；entropy 先于成功坍缩。 grasp proposal / reset curriculum、goal conditioning、demo auxiliary、PPO-CMA、intrinsic reward、archive exploration。 demo 偏置、curriculum transition gap、intrinsic reward 跑偏、高 entropy 破坏已建立接触。
7 · 长程 credit
P / A		 终端回报跨长 horizon；flat policy 同时搜索“做什么”和“怎么控制”，稀有完整成功链又不能长期 replay。 只会前半段；各 skill 单独成功但组合骤降；失败集中在 handoff；episode 变长后 value error 扩大。 options / skill hierarchy、高层 goal selector + 低层 PPO、state machine / planner、skill chaining、action chunks。 技能边界和 handoff distribution 变成新问题；chunk 越长反应越慢；上下层共同训练非平稳。
8 · Sim-to-real
P		 接触、actuator、backlash、latency、tactile 与 solver mismatch；宽而盲目的 DR 也可能稀释真实域。 sim 高、real 首轮失败；换 dt / solver 排名反转；real saturation/chatter；force/slip 时序不一致。 selective DR / ADR、SysID / SimOpt、actuator+sensing model、asymmetric teacher/student、RMA、少量 real correction。 过宽随机化导致保守且难学；高保真触觉降低吞吐；真实 correction 有安全/磨损成本。
9 · 安全约束
O		 固定 penalty 只是期望回报 scalarization，不保证峰值力、碰撞、电流或概率约束；训练探索也可能违规。 reward 上升但 violation 不降；penalty 略变就在过保守/违规间跳；平均力安全但峰值超限。 PPO-Lagrangian / PID-Lagrangian、CPO / IPO、safety critic、CBF / action projection、硬件限幅。 dual 振荡；二阶计算；shield 需要模型并制造 commanded/executed action mismatch；保守性损失 return。
10 · 尾部风险
O		 vanilla PPO 优化 E[R]；罕见 drop / crush / slip 对均值梯度很小，低 α 的 CVaR 估计又高方差。 mean 很高但 worst object / p10 很低；部署时间一长失败累积；mean 提升而 CVaR 下降。 CVaR policy gradient、EPOpt-style worst-tail update、distributional critic、adversarial domains、rare-event sampler。 尾部样本少、梯度高方差；极端场景过采样会过度保守；adversary 可能产生不物理域。
与 L20 的 wrist override 直接相关，但它不是 PPO 独有局限 joint policy 训练时执行 [a_wrist, a_finger]，部署时只执行 a_finger，改变的是闭环 transition distribution 与因果 credit。若 HUMAN 模式仍把未执行 wrist action 放进 PPO log-prob / ratio / entropy，optimizer 还会给无因果作用的维度分配 credit。应把它作为 action-intervention / occupancy mismatch 独立诊断，而不是归因给“PPO 不支持多分布”。

5. 你们的 PPO expert → Diffusion Policy 流程，研究上要分清什么

Diffusion 可能适合表达“同一物体、不同意图”的多模态名义抓姿或 action chunk；它不自动修复 wrist mismatch，也不自动提供接触稳定反馈。

标准 conditional Diffusion Policy 通常给 action / trajectory target 加噪，不是给用户输入本身加噪 用户 wrist、mode、object observation 通常作为 condition c；去噪变量是 expert action chunk x。若你们特意扰动并重建 user input，那更像 sensor denoising / masked modeling / robustness augmentation，应与 action diffusion 分开命名和消融。
训练：x_k = √ᾱ_k · x_expert + √(1 − ᾱ_k) · ε ε̂ = ε_θ(x_k, k | c_user-wrist, c_mode, c_object, c_tactile-history) 不是：把 user wrist action 当作最终要被“回归成 teacher wrist”的变量。 部署时 human wrist 始终是 executed exogenous input。
研究问题必须控制的变量失败时说明什么
多模态是否真的存在？先用 mode / goal token 消除显式意图差异，再对同 condition 的 expert finger trajectories 聚类。若 token 后单峰，diffusion 的复杂度可能没有必要。
Expert 数据是否在部署分布？只能用 wrist-intervention teacher 在 β=1 下，与 user wrist 配对的 finger trajectories；丢弃 teacher wrist action。若使用 T0 自动 wrist 数据，DP 会复现错误 occupancy，生成得再自然也可能闭环失效。
生成与反馈如何分工？区分 nominal grasp / action chunk 与高频 tactile residual；分别测 open-loop diversity 和 closed-loop hold。若长 chunk 遇滑移不能恢复，问题是 feedback horizon，不是生成质量。
混合执行比例是什么？记录真正执行的 a_exec；比较 deterministic residual、state-dependent gate 和固定 β，保持相同 wrist trajectory。随机 blend 可能把两个都可行的 action 混成不可行动作，并产生新的 train/deploy mismatch。
需要 DPPO 吗？先比较冻结 DP、DP+低层 PPO residual、DPPO fine-tune，等算力且同 expert data。只有 reward fine-tune 在稳定/尾部上带来独立增益，才支持更复杂的 generative RL。

Diffusion 不是唯一多模态方案

6. 先跑诊断，不先定 variant

以下是 research protocol：它们用于定位当前 PPO 的真实瓶颈，不是模型修改路线。每项都应在同一 object split、wrist bank、environment-step budget 和三组以上 seeds 下完成。

7. 本项目下一阶段应回答的 research questions

这些问题的答案决定后续是否改 PPO、改 actor、加 wrapper 或换算法；本页刻意不提前给出选择。

RQ1
当前 PPO update 本身健康吗？ Implementation audit 后，KL、ratio tails、value fit 和 seed variance 是否仍异常？
RQ2
多个对象的瓶颈是 coverage 还是 negative transfer？ Universal 与同预算 specialists 的 macro / worst-group gap 多大？
RQ3
显式 grasp mode / goal 能消除多少多模态？ 条件化后是否仍有多个分离且闭环成功的 action/contact clusters？
RQ4
隐藏 dynamics 占多大比例？ Privileged oracle gap、history sweep 与 tactile ladder 分别能解释多少失败？
RQ5
人类 wrist override 的损失来自哪里？ T0 direct β=1、T1 β=1 和 finger student 之间的 gap 是 occupancy、privilege 还是 capacity？
RQ6
Diffusion 的独立贡献是什么？ 在相同 human goal、expert data 和低层 stabilizer 下，它是否提高成功 mode coverage，而非只提高 open-loop 多样性？
RQ7
失败是平均性能、tail risk 还是硬约束问题？ 三者需要不同 objective / sampler / safety layer，不能用一个 reward 权重混合。
RQ8
算力扩展的边际回报还有多少？ Objects、wrist traces、environment steps 的 scaling curves 是否仍上升，还是已被 observation / simulator gap 限制？
Research 阶段的正确产物 不是“我们要给 PPO 加 GRU + MoE + diffusion + CVaR”，而是一张证据表：每个性能缺口由哪个诊断复现、哪个最小对照能消除、代价是什么、证据是否跨 object / wrist / physics split 成立。完成这张表后才写模型修改计划。
