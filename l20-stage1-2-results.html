这是 Stage 1.2 计划的第一次实际运行：用 Stage 1.1 当天采集的 95 条 Quest→retarget→L20 示教，按计划的阶梯（B0／B1／M0／方案 A／方案 B）训练并在留出的 session 上比较，附影子手视频。结论先行：抬离前 1 s，学习模型比「保持当前姿态」好 3 cm、比最近示教和常数预测好 0.5 cm；残差形式的小模型在抬离时刻误差 0.9 cm；方案 B（Flow Matching）与确定性回归无差异且候选无多模态，方案 A（VQ-VAE＋AR）停在码本重建；一个只看当前 25 维状态的线性模型在 1 s 提前量上是最好的。数据侧的两个发现比模型更重要：抓取提示与方向提示都没有在标签里留下痕迹。

本页不是 Stage 1.2 的正式结果。计划要求的 240 条、144／48／48 按 session 划分不存在；所有 trial 都是 pinch，终点标签未经人工复核（每个 session 的 stage11_training_ready=False）。这里的数字是 PoC，用来决定协议和模型下一步怎么改。

失败解剖

  • 停住等：操作者在 cube 旁停下再抓，历史窗口里全是静止，残差模型仍预测「还要移动」；A 反而对。门控层用速度可以判掉，模型层要靠更多这类样本。
  • 每个 session 的第一条：接近段包含接入后的调整动作，手腕转过 90° 以上，误差 9 cm。以后接近段只取 Quest trial 开始之后。
  • 关节限位：残差形式的预测有 4–12% 的关节越限（预测增量会把关节推出范围），显示前要裁剪。

三个结论：

  1. pinch 的执行不是瓶颈。把操作者自己的手指命令原样回放，95 条里 94 条抬起并保持，滑移 3 mm。单 cube 的 pinch 不需要学习型执行器；Stage 1.3 的第一版执行模块可以是「retarget 命令 + 门控」。
  2. Stage 1.2 的标签是姿态，不是命令。标签取的是抬离时 sim-actual 的关节角，也就是接触下实际达到的角度；位置控制要产生夹持力，目标必须越过接触面。直接把标签当命令，保持率从 99% 掉到 47%，滑移 2 cm；把标签换成抬离时刻的 retarget 命令 q_ref 后回到 96%。1.2 的预测目标因此改为 q_ref 空间（阶梯已重跑，见下）。

生成式抓取模型：一条真人数据都不用的预测器

一句话。用生成式抓取模型（Dexonomy 在 L20 上做物理抓取合成 + DexLearn 条件归一化流）产的数据、不碰任何真人数据训练的预测器，在 95 条真人上失败：抬离前 1.0 / 0.5 / 0 s 掌心误差 12.1 / 10.9 / 9.0 cm（DexLearn）、12.6 / 10.6 / 10.2 cm（Dexonomy 直出），比「保持当前姿态」（4.56 / 3.48 / 0.97）还差。原因不在掌姿——生成数据的掌姿分布与真人一致——而在关节构型：真人抓取时的拇指与非任务手指姿态不在生成数据的支撑里，输入窗口里的 16 个关节指令通道把模型推出了训练分布。把关节通道去掉，掌姿部分能迁移（1 s 前比保持好 0.8–1.0 cm）；换成覆盖式模板，全输入回到 5.7 / 4.1 / 2.9 cm。但没有一个零真人的臂过验收线（≤ 3.15 / 2.31 / 1.51 cm），抬离时刻全部差于保持；与真人混合或预训练也没有增益。在线部署不变（仍是 v7 的混合模型）。

是不是随机化不足？（2026-10-05 补记，只做分析、没有新训练）关节这一块是，而且随机化能修：关节通道带来的额外误差（全输入减只用掌姿，1 s）规范模板 8.6 cm、DexLearn 7.8 cm、覆盖式模板 0.7 cm；抬离时拇指 roll／yaw 的标准差规范 0.07／0.05、覆盖式 0.19／0.30、真人 0.27／0.44 rad，真人拇指落在某个生成抓取 0.1 rad 内的比例由 0 % 升到 65 %。规范版没覆盖到有三层原因。① 模板驱动：Dexonomy 只在物体、接触位置和手位姿上多样，手指构型由模板定死；真人实际停住的构型 100 % 落在覆盖式模板的锥内（对向 ≤ 60°、朝向 ≤ 57°），0 % 落在严格对向附近。② 输入是操作者的指令，不是机械手的构型：VR 没有触觉，人手穿过虚拟方块继续合，5.4 cm 方块上真人指令的指垫间距只有 2.2 cm、对向偏离转到 54°；Dexonomy 的加力指令沿指垫法向推，同样捏过头（3.2 cm）却保持对向（32°）——差别在方向而不在深度。IK 库的指令像真人（2.0 cm、61°），是因为它的加力偏置抄自录像。覆盖式的非任务手指 roll 以 0 为中心随机，真人无名指／小指稳定在 −0.19。③ 时间维度（由平均轨迹推断，未做反事实）：生成器里手指与手掌同步合拢（规范数据抬离前 2 s 到抬离，拇指 yaw 0.46 → 1.02、食指 0.33 → 0.95），手指构型成了「掌还剩多远」的进度钟；真人拇指 yaw 全程约 0.55，开始就半屈（拇指 roll 0.91、中指 0.97），合拢主要是最后 1 s 的食指屈曲和拇指 roll。真人抬离帧因此像合成数据的抬离前 1.5–2 s（掌还在 11–15 cm 外），与规范模型在抬离时刻 10.2 cm 的误差对得上；覆盖式配 v5 接近仍崩（12.9 cm）可用中指同样解释（合成 0.92 → 0.55 张开，真人 0.97 → 1.16 合拢）。覆盖式只随机了终点；要稳，还得让手指与进度脱钩，或直接不给关节通道。但随机化补不到真人水平。真人数据上 16 个关节通道本来只值 0.14／0.07／0.06 cm（只真人臂全输入 2.41／1.85／0.91，只用掌姿 2.55／1.92／0.97），关节随机化做到完美，Dexonomy 也只到约 3.9／3.1／1.7 cm，不过验收线。剩下的差距在掌姿与接近运动，往下每一步都要加真人信息（只用掌姿，1 s）：Dexonomy + 零真人接近 4.06 → 换真人统计标定的接近 3.67 → 真人种子 IK 终点 + 零真人接近 3.28 → 再换标定接近 3.15 → 移植真人运动 v3f 2.51（只真人 2.55）。随机化能把分布撑宽，却不能把概率质量挪到人真正抓的位置和真正的减速方式上。

在线学习：基座学抓取，每次抓取学这位操作者

一句话。零真人生成数据训练的预测器（v8）单独用过不了验收线；在它上面加在线学习——每次成功抓取在抬离那一刻就有现成的答案，当场学进去——在 95 条真人按录制顺序的逐次模拟里，第 5–7 次抓取就降到验收线以下（近 5 次中位，1.0 与 0.5 s 同时）。调参没用过的 52 条正式试次上：全网络微调 1.86 / 1.54 / 0.89 cm、线性修正 1.66 / 1.41 / 1.55 cm（1.0 / 0.5 / 0 s），不学习 4.02 / 2.52 / 1.33，保持当前姿态 4.08 / 2.99 / 0.94。生成数据基座的价值在前 40 次：同样的在线数据从零训练的模型在第 11–20 次 1 s 前误差 4.9–6.3 cm，基座 + 在线学习 2.2–4.0。现场版已接进实时预测器（默认全网络微调，每次更新约 0.1 s），待用户实测；部署默认不变。

第一步：数据生产还剩多少空间。v8 的补记说零真人数据的关节问题来自「手指与接近同步合拢」的进度钟。本轮实测修法：手指指令与接近进度脱钩——起始姿态、终点、合拢开始时刻与时长都随机，四分之一的 trial 不合拢，标签不变；规范 Dexonomy 抓姿库 + 无真人先验接近，同协议 5 种子：4.02 / 3.68 / 2.19 cm（同步合拢 12.63 / 10.55 / 10.24，种子范围 1 s 从 8.2–25.6 收窄到 3.6–4.4；只用掌姿 4.06 / 3.14 / 1.77；保持 4.56 / 3.48 / 0.97）。崩溃去掉了，1 s 追平只用掌姿、比保持好 0.91 [0.63, 1.22] cm，越近抬离越差于只用掌姿。零真人数据生产的空间基本用完：剩下的差距是人的掌姿与接近习惯——正是在线学习要补的。

标签从哪来。实时预测器每 20 ms 收到头显的完整遥测；抬离（该 trial 第一个 Transport）那一帧的手掌位姿换到物体系就是这次抓取的标签：方块用物体的完整姿态（手握住以后与取哪一帧无关），球／圆柱用世界轴；手指部分取最后一条指令（q_ref 标签）。头显报 success 才学，drop 与没有结果的只存盘，与数据集的筛选一致。一次抓取按数据集同一切法（抬离前 ≤ 3 s，每 0.05 s 一个 1 s 窗）变成 40–57 个训练窗。在 2026-10-04 的 demo 录像上回放：两次抓取的抬离时刻与数据集差 16／3.5 ms，标签位置差 0.81／0.64 cm。

数据生成审视：同步问题已解、来向问题未解、真人数据只能供终点与节奏

一句话。① 「接近与手势同步」已经解决——它是公式接近生成器的性质，v9 的手指脱钩把全输入从 12.6 修到 4.0 cm；「没有连续的人类接近」没有解决——所有公式接近仍与真人完全可分，上限就是只用掌姿（≈ 3.9 / 3.1 / 1.7）。生成器本来就是「终点 × 接近运动 × 手指指令」三个模型拼的，缺的只有一个能给出正确来向的接近模型，而有证据的来源只有这位操作者自己（v3f、在线学习）。② 真人数据能用、链条也在（导入 → 接触感知重解 → 加力 + MuJoCo 闭合 → 移植 → 筛选），但判别实验说明 DexYCB 的来向差异不是抓取类型造成的：同一个人的精细抓取也从小指侧 + 掌法向贴上去，与操作者相差 96°–114°，几乎没有一条在 45° 以内——所以没有下载其余 9 个 subject。补跑的「DexYCB 运动 + 手指脱钩」把 v10 的全输入 6.64 / 6.27 / 7.11 修到 3.59 / 3.37 / 2.02 cm，是目前最好的零本项目录像全输入基座，仍在只用掌姿的上限、三个时刻都不过线；只用精细抓取的运动池反而更差。真人数据的价值在物理闭合后的终点（更多物体）与末段节奏，不在接近。③ 场景换成 YCB 子集（有网格、有实物、有 benchmark、有同物体的真人数据）是可行的建议，由用户决定；前提是物体编码与多物体测试集。

实验 3 · 会自适应的仿真操作者（Q2）

与已有的两个仿真人的区别：Stage 1.3 的人群 v2是物理辅助的闭环——机器人的手指按 α 自己合拢，仿真人在关节空间里有缺陷并对辅助作出反应（迟滞、让步、减力），被评的是 RL 残差策略的抓取成功率；Stage 1.4 的 H2Hist（1.3 结果 v5，即 Q6）是把会话历史编成策略的输入，没有增益。本节是纯显示条件（Stage 1.2 的影子手，没有物理辅助）：仿真人改变的是终点（向看到的预测靠拢），被评的是预测器自己在闭环里的收敛与偏差，不是策略的成功率；两边用同一个概念（conformance／αh），对象不同。每次抓取：当前模型在自然录像的 1 s 评测窗上的预测 = 操作者在抬离前 1 s 看到的影子手 ŷ；操作者的实际落点 y′ = y + g·(ŷ − y)（只动掌心位置；影子离 intent 超过 6 cm 时不跟）；最后 1 s 的掌心轨迹按 smoothstep 渐变到新落点，训练窗与评测窗都从扭曲后的轨迹重切；模型在扭曲后的评测窗上打分两次——对 intent（自然标签）和对 realised（实际落点）；然后学 (扭曲窗, y′)。增益 g = 0（= 实验 1）、0.25、0.5、以及「信任」规则（g = 0.5·clip(1 − 近 5 次影子手误差 / 4 cm)：影子越准人越跟）。臂：不学习／线性修正／微调／混合，两条流，随机方法 2 个种子。这是什么：在明确行为规则下的闭环稳定性检验；不是什么：任何真人的模型——没有一位操作者在看着影子手的条件下被系统录过（10-04 两条、今天六条），g 无法校准。

补记 · p(a | o) 直观图：这个人的抓取是生成分布里的低概率模式，还是另一个分布？

用户问基座能不能学到「抓取」这项技能本身、人用的不同的 a 是同一分布里的不同概率还是不同的分布、有没有可视化。做法（training/artifacts/stage12_intent/online/study_v14/diag_pa_given_o/）：对 95 条真人的每个评测窗，在基座的归一化掌姿通道上找生成数据（gd_free 的 cube054，612 条）里最近 1 秒运动最像的 50 个窗、和操作者自己其它 trial 里最像的 25 个窗，画它们的抬离掌位——两边的经验 p(a | o)。结果（95 条中位，1.0 / 0.5 / 0 s）：生成云的离散 7.0 / 5.5 / 2.6 cm，离真实落点最近的生成样本 5.8 / 6.6 / 5.6 cm，没有一个生成样本在 2 cm 内（只按末帧掌心位置匹配也是 3.2–3.6 cm、0 %）；操作者自己的云离散 1.9 / 1.8 / 1.5 cm、最近点 1.2 / 1.1 / 1.0 cm、40–52 % 在 2 cm 内；不加条件时整个生成终点集合离操作者终点最近 3.2 cm（37 % 在 2 cm 内）。基座 4.2 / 2.9 / 1.3 cm 好于生成云的局部均值 7.1 / 7.8 / 8.7（网络在插值，不是查表），留一 trial 的线性修正 1.7 / 1.5 / 1.4 逼近操作者云的离散。

怎么读。① 给定同样的运动，生成数据会去的地方离这个人真正去的地方 5–7 cm，所以不是同一分布里的低概率模式，是另一个条件分布：「什么运动通向什么终点」这张映射是这个人自己的；生成终点集合只粗略覆盖了落点区域（3.2 cm），差的是 p(o | a)——人怎么靠近，与 v10、v13 的结论一致。② 基座能学的「技能」是几何：对这个物体哪些掌位是物理上可行、稳定的抓取（生成库是物理复验过的）；学不到的是这个人从哪条路靠近、停在可行集的哪一点。③ 对建模的含义：单人内 p(a | o) 是单峰的（v1 的 FM 在这位操作者上 = M0 + 0.7 cm 抖动），跨人群的多模态在生成基座里存在（1 s 时离散 7 cm），但新人的模式不在基座的模式上，所以「保留基座的多模态、在线只学一个选择器」现在行不通，必须像微调／线性修正那样平移映射；要让选模式成立，生成分布得先把人包进去（操作者风格挂点 + realism 检查），那时再比 FM 基座 + 选择器 与 M0 + 平移。

怎么读。侧捏是补覆盖，不等于会泛化：产率与通过率是合成域内的数字，是否解决了午餐肉罐那类失败只有回放那一次能看。侧捏家族基座在物体顶面上 9.3 cm（上方 14.6）——先验旋转 60–90° 后是「斜侧」；长物体（午餐肉罐深 8.7 cm、布丁盒长 11.3 cm）的侧捏只有靠近操作者一端的候选够得着，产率 6 / 10 每 480——下一轮把侧捏候选偏向近端或放宽旋转角。「远处侧捏状态预测落在两家族之间」的比例三臂都是 0：回归器按当前状态选家族，没有平均；但远处状态是沿各抓取自己的来向采的，「同一个位置两种抓法都可能」本轮没有构造，这才是生成式可能有用的情形，要操作者自己的数据才看得到。
