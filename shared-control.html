共享控制路线：从 To the Noise and Back 到 EMG 灵巧手
参照论文的流程、它的实验、我们的架构与当前进度

参照论文是 To the Noise and Back: Diffusion for Shared Autonomy（Yoneda et al., RSS 2023, arXiv:2302.12244）：用扩散模型的「部分加噪 + 去噪」把用户动作拉回专家分布，不需要知道用户目标、不需要 reward、不需要在线人类参与训练。本页把它的流程和实验讲清楚，然后对照我们的系统：EMG 采集 → emg2pose 解码手指、Quest 只供 wrist pose、MuJoCo 里的 L20 共享控制——同一套配方，但动作空间从他们的 2–3 维升到 16+6 维。我们目前在 RL 阶段生成专家数据（论文也是这么造 demo 的），正在找合适的长程任务。

§ 1论文的核心想法与流程

共享自主（shared autonomy）里，copilot 要在「尊重用户意图（fidelity）」和「把动作拉向安全/有效的专家行为（conformity）」之间做取舍。传统做法要么要知道环境动力学、要么要一个离散的目标集合做意图推断、要么（deep RL 一系）要任务 reward 和人在环训练。这篇论文把三样全部扔掉，只要一样东西：一批能代表「期望行为」的专家轨迹。

训练（就是标准 DDPM，见DP 推导页）

收集专家演示（目标随机采样；把目标从 observation 里删掉再训练——copilot 永远不知道用户想去哪），训练一个状态条件扩散模型：

$$p_\theta(a_t \mid s_t) \qquad \text{loss}=\mathbb E\Big[\big\|\epsilon-\epsilon_\theta\big(\sqrt{\bar\alpha_k}\,a+\sqrt{1-\bar\alpha_k}\,\epsilon,\;k\mid s\big)\big\|^2\Big]$$

训练全程不需要用户模型、不需要 surrogate pilot、不需要 reward。用户的策略只在推理时进场。

推理：部分正向 + 部分反向（partial diffusion）

Algorithm 1 · Shared autonomy as partial diffusion
  1. 输入：状态 $s_t$、用户动作 $a_t^h$；超参：forward diffusion ratio $\gamma\in[0,1]$，扩散总步数 $K$
  2. $k_{sw}\leftarrow\lfloor\gamma K\rfloor$（切换步）
  3. 正向：$\tilde a\leftarrow\sqrt{\bar\alpha_{k_{sw}}}\,a_t^h+\sqrt{1-\bar\alpha_{k_{sw}}}\,\epsilon$ —— 把用户动作加噪 $k_{sw}$ 步（闭式一步到位）
  4. 反向：从 $k=k_{sw}$ 起用 $\mu_\theta(\cdot,k\mid s_t)$ 逐步去噪回 $k=0$
  5. 输出共享动作 $a_t^s$
为什么这一步就完成了仲裁。正向扩散「破坏」用户动作里的信息，反向去噪把它「投影」回专家分布——$\gamma$ 控制破坏多少： $\gamma$ 小 → 原信息保留多、输出离 $a^h$ 近（高 fidelity，低 conformity）； $\gamma$ 大 → 信息几乎清零、输出就是从专家分布里重新采样（低 fidelity，高 conformity）； $\gamma=1$ 退化为完全自主。论文还给了正式的界（式 10）：$\|a^h-a^s\|$ 的上界随 $k_{sw}$ 单调增长——copilot 偏离用户的程度是可控的。 关键前提是用户意图在专家分布下有非零概率：demo 里同时包含到各个目标的轨迹（多模态！），去噪会把用户动作拉向离它最近的那个 mode——意图不需要被显式推断，它藏在「用户动作靠近哪个 mode」里。这正是上一页说的「score field 把球滚进就近盆地」。

§ 2交互演示：$\gamma$ 的 fidelity ↔ conformity 取舍

下面用一维双峰专家分布（±2 两种抓法）复现论文 Fig. 2 / Fig. 4 的机制。拖动 $a^h$（用户动作，可以故意选一个又偏又烂的）和 $\gamma$，采样看输出分布怎么在「贴着用户」和「贴着专家」之间移动：

蓝线 = 专家分布 $P_{\text{demo}}$；红色竖线 = 用户动作 $a^h$；橙色直方图 = 共享动作 $a^s$ 的分布（精确 DDPM 部分扩散模拟）。 $\gamma\!\approx\!0.1$：输出紧贴 $a^h$（几乎不帮忙）；$\gamma\!\approx\!0.3$：输出被拉进离 $a^h$ 近的那个 mode——修正但保意图，这是论文实验里的最优区间；$\gamma\!\to\!1$：输出无视 $a^h$、按专家分布整体铺开（60/40），意图丢失。论文的结论曲线一模一样：成功率随 $\gamma$ 先升到临界点再回落。

γ 扫描的形状（Fig. 5/6）：成功率随 γ 上升到一个临界值后回落——γ 太大时 copilot 无视用户、按训练分布均匀选目标，正确目标率跌向 50%。坠毁率基本随 γ 单调下降。Expert pilot 配 copilot 不掉分（LL 77.7→78.7）：帮不了但也不添乱。问卷上（helpful / consistent / responsive / collaborative / trustworthy 五项 Likert）copilot 全面高于直接遥操作。
但注意它的实验有多「小」。动作全部是 2–3 维、状态十几维、episode 几百步、目标二选一或平面上一个点。整套方法在这个尺度上闭环成立——它在高维灵巧手上是否成立，正是我们要回答的问题（§4）。

§ 4映射到我们的系统：同一配方，维度抬高一个量级

论文的组件论文的实现我们的对应物

为什么我们「目前在 RL 阶段」是这条配方的正确一步。论文的整个方法只需要一样输入：$P_{\text{demo}}$。他们用 SAC expert rollout 造出来——我们同样用 RL（Playground fork 里的 L20 env + PPO，4090 上 Warp 后端）造。区别在难度：他们的 expert 是「2 维推力降落」，我们的 expert 要在 16 自由度欠驱动手上完成抓取和使用工具。expert 质量直接决定 copilot 的上限——这就是为什么 reward 设计（锤钉的 legit-depth 记账、pregrasp 课程）值得反复打磨。
维度账。论文：动作 2–3 维，$P_{\text{demo}}$ 是低维分布，单步生成。我们：单步 $u\in\mathbb R^{16}$（手指）+ 6 维手腕由人独占；上 chunk 后 $A\in\mathbb R^{16\times H}$（H=16 时 256 维）。这正是 DP 推导页 §6 的论点落地处：低维时 MDN/单步 DDPM 都行，高维联合分布（指间协调 + 时间一致性）才是 diffusion 表示的主场——也是我们相对论文的增量主张。同时它带来论文没有的开放问题：partial diffusion 的 γ 界随维度 $d$ 变松（式 10 里有 $d$）、去噪延迟要过 100 Hz 控制环、chunk 级仲裁怎么与逐帧张手 override 共存。

与论文架构的一个刻意差异。论文的 copilot 每步重采整个动作；我们 Phase 1 采用 residual + α 而不是直接 partial diffusion——因为手腕必须无条件归用户、且要保证「张手一个控制周期内解除辅助」这类硬性 fail-safe。partial diffusion 的 γ 路线是 Phase 1 之后的模型升级：把 residual 换成 DP chunk 模型后，γ 和 α 扮演同一个角色（都是 fidelity↔conformity 的旋钮），且 γ 有论文那条随 $k_{sw}$ 单调的偏离上界可引用。

6.2 RL 专家（当前主战场）

  • 环境：Playground fork 注册 l20_hand，已有 reorient（掌内重定向）、pick_cube、hammer_nail 三个 env。
  • 锤钉一弧已收口：reward 迭代到 v4（瞬时门 → 锁存链 → 「打击必须来自锤子」的 legit-depth 记账 → 30% 锤在手课程），6/6 评估 episode 用锤子把钉打入，reward 7533。
  • 训练系统：4090 为日常主力；Warp 后端跑通（warp 1.11），一轮训练从 36 分钟压到 7 分钟——reward 迭代周期因此才转得动。
  • 正在找长程任务：shared control 的 demo 要覆盖「接近 → 预抓取 → 抓稳 → 使用/搬运」的完整多阶段行为，纯 reach/lift 太短。hammer_nail（抓工具→用工具）是现有最长的一条；teleop 侧已接入 dexjoco 的 Hanoi 场景（三盘两柱，天然长程多步）与关节夹持器（tongs）物体，是候选池；仍在扫描能在 MJX/Warp 尺度训得动、又够长的任务。

6.3 EMG 线（并行，spec 三阶段）

  • Phase 0 骨架 ✅ 验收通过：无硬件全流程，pytest 全绿，fake session 过 verify。
  • Phase 1 真实采集 代码就位，验收未跑：串口 supervisor、Quest 源、daemon+Web 三页、软件互相关同步（腕带 IMU × Quest 手腕）都在；差的是戴上腕带真录 5 分钟并让 verify 五族全过。
  • emg2pose 解码器：emg/training 子应用框架在（HDF5 导出兼容 emg2pose 基线），等 Phase 1 的真实数据。
  • 注意 Phase 1 共享控制计划明确不含 EMG——EMG 顶替 Quest 手指输入是共享控制验证之后的下一阶段,两条线并行推进互不阻塞。
一句话总结当前位置。遥操作平台已建成并测量到干净（论文里那种「pilot→系统→物理→显示」的闭环我们有了，而且是 16+6 维的）；论文配方里唯一缺的原料是 $P_{\text{demo}}$——所以现在的全部火力在 RL expert 上：reward 打磨完锤钉，训练一轮 7 分钟，正在选长程任务扩 demo 覆盖面。expert 数据一到位，路线就是：residual policy（Stage 4）→ α 仲裁（Stage 5）→ 用户实验（Stage 6–7）→ 换 DP chunk + γ 的模型路线。
