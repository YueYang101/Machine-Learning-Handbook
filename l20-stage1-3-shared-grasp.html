§ 1 · 预测抓姿之后，还缺什么？

Stage 1.2 的 A（No-Gaze VQ-VAE＋自回归 Transformer）输出未来手部序列，B（Flow Matching）首轮输出多个最终抓姿候选。它们的标签来自 Stage 1.1 数采，表示想达到的 L20 抓姿，尚未证明承重或抗扰。

相同的最终姿态，可以对应不同的闭合指令、接触过程和执行结果
模块输入 → 输出本阶段取舍
意图预测用户手部历史 → 未来抓姿／序列复用 1.2 冻结模型；同时保留实时用户参考
候选选择与几何修正预测候选＋cube／L20 几何 → 可行目标或拒绝先用现有示教、FK 与优化，不新训通用抓姿生成器
闭环执行实际机器人状态＋目标 → 当前关节命令先基础控制；按失败证据升级目标条件 RL／有界残差

单一 cube 消除了目标类别识别，仍需要物体相对位姿与接触反馈。首轮仿真可读物体／接触真值；实机需要另行明确哪些量可测或可估。几何无穿透、预测误差低、稳定持物是不同指标。

第一轮检验用户指定抓法的接近、闭合与短时保持；独立报告接触形成和物理保持。只有解除物体固定／支撑后的测试才能说明承重。搬运、抗扰、复杂手内操作与完整 release 流程后续逐项扩展，不倒加为 1.1／1.2 的验收条件。

§ 2 · A／B 共用一个执行接口

Quest 历史 → 1.2 A／B → 抓姿／轨迹候选
↓ 按实时输入一致性、可行性与时间连续性选候选；不平均不同抓法
几何修正 → 目标抓姿 g
↓ 与用户实时 retarget 参考、确认／取消状态汇合
共享控制：目标选择、执行进度、辅助强度
↓ 目标＋实际 L20 状态＋可用物体／接触反馈
目标条件执行模块 → 当前关节命令 → L20
↺ 读取执行后的真实状态，重新规划／修正下一步

上图是接口示意，没有暗示 controller、候选评分器或置信度模块已经实现。

目标表达：沿用物体坐标系中的掌部位姿与 16 个主动关节参考 g = (T_OP, q_goal)，保留关节顺序、单位、耦合定义与坐标版本；可通过 FK 派生指尖目标和接触候选。A 可提供序列子目标，B 需先选择终点并生成接近／闭合参考。首轮 A／B 统一比较终点条件执行，序列优势另报。

目标与动作：q_goal 表示几何目标；控制器根据当前实际状态输出 q_cmd 或有界修正量。接触时的关节目标误差会影响作用力，不能把几何终点无条件当作闭合／承重指令。

腕部权限：首轮腕部保持用户／外部控制，手指负责局部辅助；掌姿预测用于提示、可达性判断和目标选择。掌姿不可达时拒绝或请求用户调整腕部，不通过手指强行补偿；自动控腕属于后续单独对照。

用户主导进度：预测终点提供辅助方向，当前用户输入决定是否继续。首轮先用明确启用／确认建立可解释基线，再验证自动门控。取消或覆盖应撤销旧目标；“停止辅助”与“立即张手”分开，释放用独立明确输入。低可信或库外输入退回实时控制，不因训练集多为闭合动作而持续帮用户握紧。

候选采样数量、时序一致性与可行性只能提供评分线索，不能直接当作校准置信度。选择／拒绝规则在 validation 上确定，冻结后进入测试；不使用真实未来终点做在线候选排序。

§ 3 · 执行模块按缺口升级

当前先做可解释基线；后两项是按实验结果启用的候选
实现什么时候用所需数据／验证
几何修正＋基础闭环当前首选：受限轨迹跟踪、分阶段闭合；优先定位不可达、穿透、接近错误已知模型与可行目标；记录实际状态、控制目标、接触与失败
Goal-conditioned RL／residual policy目标合理但滑移、丢接触、扰动恢复反复失败时仿真交互或完整执行示教；输入实际状态与目标，输出关节命令／有界残差
DexGen 式生成控制器已有足够机器人动作数据，需要覆盖多种操作模式时成功执行与恢复轨迹、状态—动作配对；独立训练动作先验，不能只复用 1.2 的终点标签

若训练执行 policy，目标跟踪、抓取稳定、动作平滑和限位／碰撞约束共同定义任务，实际权重在首个 run 登记。变化起始状态与目标抓姿，保留不同接触指和抓法；只奖励“拿起”可能使策略忽略目标而总选同一容易抓法。先用正确目标验证，再加入预测误差与目标切换。

1.1 示教可提供目标与初始化参考，但当前记录尚未验收稳定抓取，因此不能直接称为机器人执行专家数据。训练执行器需要额外物理 rollout 或成功示教，保留恢复过程与失败原因；共享控制导致的偏离状态也应覆盖。

可复用资产的历史核验与本体缺口见 抓姿来源选型综述。本页不重新宣称已有 planner／policy 已适配 L20；实现时核验最新模型、关节耦合、传感和接口。基础控制、已有策略与新训策略都必须按同一协议验收。

§ 4 · Reference：DexterityGen（DexGen）

DexterityGen: Foundation Controller for Unprecedented Dexterity，Zhao-Heng Yin、Changhao Wang 等，RSS 2025。会议原文 · 可读全文（v1） · 作者项目与视频。

仿真 RL 学习旋转、平移与抓法转换
↓ 采集机器人状态、关键点运动与实际控制动作
训练 diffusion 动作先验＋逆动力学模型
↓ 部署：当前本体状态作为条件，人类粗动作引导 diffusion 采样
短时关键点运动 → 逆动力学 → 关节位置目标

原文用 diffusion 学习给定机器人状态的短时关键点运动分布，再以 inverse dynamics MLP 将运动转为关节目标；人的动作作为采样梯度引导。训练数据主要来自仿真 RL 产生的动作，物理执行能力来自这些交互数据。我们借鉴“人提供目标、低层先验辅助执行”的分工。

与 Stage 1.2 B 的区别：1.2 B 学的是“用户未来希望的手姿”；DexGen 学的是“机器人当前状态下的动作分布”。即便都采用 diffusion／Flow Matching，训练标签与部署职责仍不同。沿用架构思想不等于复现 DexGen，也不等于已有可用权重。

代码／权重／数据核验（2026-09-13）：作者页的 Code (I)：Lightning Grasp 指向抓姿生成引擎；该入口不是完整 DexGen diffusion／逆动力学控制器。本轮未核验完整控制器 checkpoint、RL 轨迹数据或 L20 适配结果。原文实机为 Allegro＋Franka，L20 需要重新对齐运动学、耦合、观测、动作和动力学数据。

首轮适配：先以小型目标条件控制器验证单 cube 辅助，暂不复制 DexGen 的大规模 RL→数据生成→diffusion 训练链。若后续建立动作先验，1.2 的预测可作为额外引导，但必须与实时用户参考比较，验证是否改善提前量而非放大错误预测。接触后的复杂换抓与工具使用保留为后续研究。

相关路线：TeleDexter（Li 等，2026 预印本）参考目标条件 RL 接触执行；DiSCo（Wang 等，2026）参考用户动作引导的 diffusion 序列辅助。二者是方法背景，本阶段不承诺复现；共享控制理论与部分扩散说明见 系统路线。

T1／T3 使用相同预测器、候选选择和门控规则；T2／T3 使用相同执行器、初态与目标抓法分布。另以相同人工目标对基础与专用控制器做配对测试，隔离执行收益；如需判断预测是否必需，在 T3 中关闭预测、保留实时参考作消融。比较 A／B 时固定下游控制器。

共同记录：目标抓法／接触指保持程度、接触形成成功率、短时保持成功率与掉落、完成时间、辅助修正幅度、用户覆盖／取消响应、推理和控制延迟。按抓法、方向、初态与 session 分层，失败分为预测错误、目标不可行、执行失稳和仲裁错误。

测试前在 validation 冻结成功定义、保持时长、允许误差、控制预算与样本分母；物理保持明确物体是否固定、支撑／腕部运动条件。1.2 的 session 划分继续隔离；执行策略开发不使用其 test trial 的未来标签，测试目标只用于评测。新增执行数据独立登记划分。

继续判据：先让 T2 在正确目标下可靠工作；T3 应在保持用户抓法的前提下优于基础控制。若只提高拿起率却频繁改变抓法，或预测辅助不优于实时参考，应调整相应模块。不给尚未运行的方案预填成功率和提升阈值。

§ 6 · 进入 Stage 1.3 后执行这五步

  1. 冻结接口与案例。读取 1.2 模型／normalizer／split 版本；统一目标、实际状态、腕部权限及确认／取消输入。交付接口说明与少量候选回放，待生成。
  2. 先验证正确目标。在单 cube 仿真中用人工确认目标测试几何修正和基础执行；记录接触、保持与失败，得到是否需要学习型执行的依据。
  3. 建立预测辅助对照。跑 T0／T1，固定门控和控制器；比较预测带来的收益、错误和用户覆盖响应。
  4. 按缺口启用专用执行。需要时适配已有控制器或训练目标条件 RL／有界残差，完成 T2；成功后接入预测跑 T3。DexGen 式生成执行保留为数据充足后的分支。
  5. 冻结评测并登记结果。配对比较、保留失败回放；记录 run ID、模型／资产版本、实际配置、样本分母、结果与下一步。决定保留基础方案、升级执行器或补数采。
