Stage 1.2：Training

使用 Stage 1.1 冻结的单一 cube Quest→retarget→L20 示教，并行尝试两个 Human Model：A 是删除 gaze／物体分支的 Gaze-Guided VQ-VAE＋自回归 Transformer；B 是条件 Flow Matching 生成预测。两者都只根据尚未完成的手部动作前缀预测未来，不直接输出机器人当前控制命令。

当前 v11（2026-10-07）：在线学习的两个改进，都在 v9 的逐次模拟里测——把线性修正与全网络微调按「离终点还剩多远」加权混合，调参没用过的正式试次上 1 s 前误差少 27 %、抬离时刻不变；基座和在线学习加输出「未来 1 s 掌姿 + 接触点」只让基座好一点，在线学习没有更快；现场部署不变，数字见结果页 v11。v10（2026-10-07）：现阶段问题：生成式数据库产生的轨迹不连续，不符合模型的输入——模型的输入是连续的 1 s 运动，生成式抓取库只给离散的抓取姿态；v10 把公式补的运动换成公开数据集 DexYCB 的真人伸手抓取，只补上了旋转节奏，零「本项目录像」的基座仍在 3.8–4.1 cm（1 s），数字见结果页 v10。v9（2026-10-06）：在 v8 的零真人基座上加在线学习——生成数据训练的预测器负责抓取，在线学习从这位操作者每次成功抓取里学习惯；离线逐次模拟第 5–7 次抓取过验收线，现场版已接进实时预测器、待用户实测，数字见结果页 v9。v8（2026-10-04）：生成式抓取模型（Dexonomy 合成 + DexLearn 生成）产数据、完全替代真人数据训练预测器——未过验收线，在线部署不变（仍是 v7 的混合模型），数字见结果页 v8。v5–v7 是合成数据这条线：09-23 建了抓姿库与接近生成器并接进现有模型（v5），09-30 独立评估说明数量不是瓶颈（v6），当晚改成围绕真人轨迹的移植式生成器 + 筛选 + 五臂协议（v7），数字见结果页同号锚点。2026-09-13 在 pilot + 正式 session 1 的 95 条 pinch 示教上跑了首个 run，此后三轮（q_ref 标签与消融、实时预测器与置信度、联合模型）的结果与视频见 Stage 1.2 结果（实验记录）。本页保留模型与比较协议；计划中的 240 条 144／48／48 划分已被 Stage 1.1 v3（四物体、campaign v2-objects）取代，见 Stage 1.1 v3，v3 数据上的结果待采。

明确是两个方案：方案 A 学离散 motion token 的序列条件概率，目标是复现“动作前缀 → 到接触为止的未来序列”；方案 B 学连续未来手姿的条件分布，目标是避免不确定时只输出一只“平均手”。它们共享数据，但编码、loss 和推理过程都不同。
小数据取舍：240 条 trial 可能不足以同时稳定训练 codebook、Transformer 和高维轨迹生成器。因此 A 保留论文式完整序列任务；B 首轮只生成物体坐标系中的多个最终 L20 手姿候选。两者先在相同终点指标上比较，不把不同额外能力混成一个总分。

路线复盘：Stage 1.4 阶段性总结与待决问题 汇总最新讨论；本页保留本阶段协议，不把讨论方案回填为已完成验收。

输出口径：现有 M0／终点模型预测抬离时的最终抓姿；过去一秒是输入窗口，抬离前一秒是评测位置，FMS 的未来一秒才是固定输出时域。下一轮的实时最终目标与物体约束见 1.4 输出讨论。

各版本的协议要点

v1（2026-09-13）：数据 = Stage 1.1 v1（43 条 pilot）+ v2（52 条正式 session 1），95 条 pinch，7 折留一 session；输入 = 抬离前 1 s 的 TOH 窗口 + 手形 + 追踪有效性，标签 = 抬离时刻（Quest Transport 相位首个样本）的 TOP,T 与 16 个实现关节；阶梯 B0 保持 / B1 最近示教 / M0 MLP（残差形式）/ 方案 A VQ-VAE+AR / 方案 B Flow Matching，另加序列生成器 FMS、DPS。

v2（2026-09-13 晚 – 09-14）：标签关节改为抬离时的 retarget 命令 qref（run qref-abs／qref-res），因为物理预检证明实现姿态是接触下的结果不是命令；输入消融后可部署预测器只用当前 25 维状态（腕相对 cube + q_ref）。

v3（2026-09-14）：同一模型以 UDP 接入 quest_teleop.py --live-udp 实时预测并在头显画 ghost hand（仅显示，session 记为 demo，不入训练集）；接触点头 + 先验；置信度 = 剩余位移 + 0.3 s × 掌速的启发式门控（6 cm 阈值，滞回），仲裁系数 = 0.5err/6 cm 传给 Stage 1.3 的 α。

v4（2026-09-16）：JointNet（编码器 → pose 25 + contacts 6 + logvar 9），变体 sep／joint／derived／nll／ens5，4090 上训练（tips cache，无 MuJoCo），Mac 上评分；部署 je（5 seed 均值，实时按键 6）。下一版将在 Stage 1.1 v3 的四物体数据上重训，并增加“要抓哪个物体”的目标识别头（输入加入全部物体位姿）。

v5（2026-09-23）：合成数据进入训练。抓姿库：6 种基元（cube 4／5.4／7 cm、圆柱、球、长条）× pinch／tripod，接触点解析采样，掌姿种子 = 真人 95 条在捏合坐标系里的分布，DLS IK（掌姿 6 + 关节 16，耦合关节随动），cage／grasp／squeeze 三段，objects4 物理验证（合拢 → 加力 → 抬 8 cm → 晃动，滑移 < 2 cm）。接近轨迹：随机偏航 + Boltzmann 选面、最小 jerk 运输 + 慢速逼近、笼／合拢时刻与幅度随机化。模型不变（残差 M0、je 集成），输入 26 + 7 通道（物体 one-hot、尺寸×10，不归一化）。比较：合成 held-out 偏航 bin {1,5} + 每格 1/4 抓姿行、held-out cube070、全部合成 → 真人零样本、真人 7 折 LOSO 四臂（只真人 / 合成冻结 / 合成预训练+微调 150 ep@3e-4 / 同配方随机初始化）。

v6（2026-09-30）：评估协议，不改模型。缩放：合成训练 trial 12.5–400 %（抓姿行 % 4 == 0 永远留出），每个配置 3–5 种子、等梯度步数，真人零样本 + 合成留出行；真人学习曲线 10／20／40／全部（留一会话）；标签检查 = 逐关节均值／方差、任务关节马氏椭球、限位占比；轨迹检查 = 还差的腕部旋转与掌心高度随时间、绕接触中点转动的分解、真人／合成分类 AUC（对照 = 真人会话之间）；物理复验 = 加掌姿扰动／摩擦／质量重新验证，真人标签同法作参照。验收线：未参与校准的真人会话上每个时刻低于保持且 ≤ 10 条真人（3.15 / 2.31 / 1.51 cm），≥ 5 种子，预训练带同配方对照。

v7（2026-09-30 晚）：生成器 = 移植（真人 trial 相对自己终点的腕部残差在终点掌系里重放、远端渐变到世界系真人路径；手指 = 新终点 + 真人残差，非任务手指取真人；pinch 终点 = 真人抬离指令原样落座到库行的接触对上，tripod／落座失败者以真人姿态为先验做 IK；时间伸缩 0.8–1.25、残差幅度 0.85–1.15、噪声；每条记来源会话）。筛选 = 物理（3 mm/3° 扰动 2 次 ≥ 1 次持住、滑移 ≤ 1.5 cm）∧ 运动学（0.8 s 前路径不穿物 > 5 mm／不穿桌 > 3 mm）；真实性 logistic 分类器（终点相对特征，不含中指）只作权重。训练 = 3 组留一（formal 52 / pilot A 22 / pilot B 21）× 5 种子，折内不用来自留出会话的合成，分类器只用训练会话拟合；臂：只真人（300 ep）、只合成（18750 步 × 256）、预训练→微调（150 ep@3e-4）、同配方随机初始化、混合（每批一半真人一半合成，合成按权重抽）。第二测试集 = 15 个 v2-objects 会话副本上离线推导的 10 条多物体 trial（未复核；物体系改为 yaw-only／世界对齐）。部署（10-04，不另占版本号）：混合配方在全部 95 条真人 + 筛后合成上重训成 33 通道、fit-final 格式的 checkpoint；在线预测器按 checkpoint 的通道数建网，物体通道取自头显回执，物体系同上；默认在线模型不换，靠 MJQUEST_CHECKPOINT／MJQUEST_MODEL=je 切换（结果 §部署）。

v8（2026-10-04）：生成式抓取模型产数据、完全替代真人数据。终点不再来自 IK 抓姿库（其掌姿种子、关节先验、加力偏置都取自 95 条真人），改由生成式模型给出——这是第一次真正用生成器的产物进训练集（v5 的抓姿库是借 BODex／Dexonomy 思路自建的解析采样 + IK，Dexonomy 当时只冒烟过）：Dexonomy（RSS 2025，模板驱动的物理抓取合成）在 L20 上产数据，DexLearn（同组的学习式生成模型，条件归一化流：Möbius 流出旋转、MLP 出平移与三段关节，输入物体点云 + 抓取类型）在其上训练后再采样。L20 模板按 GRASP 分类（24 Tip Pinch、14 Tripod）在手的运动学上求解，非任务手指取 Dexonomy Shadow 同名标注的弯曲比例，不读任何录制；每类按开口出多个模板（pinch 3／4.5／6／7.5 cm，tripod 3／4.5／6 cm），因为 Dexonomy 先把模板刚性贴到物体表面再闭合。物体：130 个随机尺寸原型（方块／长条 1.5–4 cm 半边长、圆柱、球）训练生成模型，collection-v2 的 6 个物体留出、只采样。所有生成样本回到 objects4 场景复验（合拢、加力、抬 8 cm、±4 cm 摇晃、3 mm／3° 扰动 2 次 ≥ 1 次持住、滑移 ≤ 1.5 cm），外加两条显式的操作者侧规则（前臂不低于水平 10°、手腕高于桌面 3 cm）。接近轨迹两种：v5 的参数化生成器（不含真人轨迹，但起点／舒适腕姿／手指初态／时序是真人统计）与无真人先验的生成器（台面几何：操作者在 −x 侧、右肩位置取人体测量常识；最小 jerk 运输 + 减速逼近，最大张口在 60–80 % 运动时间；选面 = 前臂指向肩 + 前臂旋转窗口 −100°…+40°）。协议沿用 v7：残差 M0，5 种子；不见真人数据的臂只训练一次、在全部 95 条单 cube 真人 + 10 条多物体真人 + 2026-10-04 demo 录像 2 条上零样本测；参照臂（只真人、v3f）按 3 组留一。加两个诊断：只用掌姿输入（16 个关节指令通道置零，残差基准与标签不变）区分「姿态模式缺口」与「接近运动不迁移」；覆盖式模板（不只取严格对向的一个解，而在 L20 可行姿态空间里用最远点采样取 4 种拇指构型 × 2 组随机非任务手指，只放宽到指垫各自朝向对方 57° 锥内、对向 ≤ 60°）检验不靠真人能否补上姿态缺口。训练在 berlin 单卡（H200，tmux 内固定 CUDA_VISIBLE_DEVICES）。

v9（2026-10-06）：生成数据学抓取 + 在线学习学这位操作者。分工：v8 的零真人基座（只用掌姿输入的残差 M0，训练数据里没有任何真人数据）负责「怎么抓」；在线学习负责「这个人怎么抓」。标签免费：实时预测器每 20 ms 收到头显的完整遥测，某个 trial 的第一个 Transport 遥测就是抬离（与数据集的终点同一定义），此刻手掌位姿换到物体系（方块用物体完整姿态，球／圆柱用世界轴）+ 最后一条手指指令就是这次抓取的标签；头显报 success 才学，drop 与没有结果的只存盘。一次抓取按数据集同一切法变成 40–57 个 1 s 窗。更新方法：常数修正、线性修正（基座输出 + 末帧掌姿上的岭回归）、只调最后一层、全网络微调（向基座权重的 L2）；参照 = 只用这位操作者的抓取从零训练。离线协议 = 逐次「先测后学」：95 条真人按录制顺序流过，每条先预测它的 5 个评测窗（抬离前 1.0 … 0 s）再学它；超参只在前 43 条（pilot）上选，后 52 条（formal）留出；判据 = 每段的掌心误差中位、第几次抓取后近 5 次中位低于验收线、每次更新耗时。在线学习之前先做一个数据臂（用户要求先看数据生产的空间）：零真人数据里手指指令与接近进度脱钩，同 v8 协议。现场版接进实时预测器（live --online，demo 脚本 MJQUEST_ONLINE），每次抬离连同样本、标签、结果落盘作备份，由用户实测。

v10（2026-10-07）：现阶段问题：生成式数据库产生的轨迹不连续，不符合模型的输入。具体说：模型每 50 ms 看最近 1 s 的手部指令流（20 帧 × 33 通道），学「一段运动 → 它的终点」；生成式抓取库（Dexonomy／DexLearn）只给离散的抓取姿态（pregrasp／grasp／squeeze），没有通向它们的连续轨迹，零真人训练集里那一秒一直是公式补的，而公式运动与真人完全可分（只看手腕运动的逻辑回归 AUC 0.98–1.00；真人在抬离前 0.5 s 还差 10.9° 没转完，公式是 0°）。v10 的做法：终点照旧由生成式库给（Dexonomy 规范库，舒适规则选面），运动换成另一个实验室的真人——DexYCB subject 01 的 50 条右手伸手抓取（L20 hand_base_link 目标与 16 个重定向指令来自路线 A 的导入）。抬离按头显规则重定（物体沿真上方升高 2.5 cm 并保持 0.1 s），每条运动在物体系里相对它自己的抬离位姿移植到库终点，放慢 1–3 倍（零真人生成器原有的通用先验），指令路径扫过物体或桌面的丢掉。不用本项目任何录像。判据同 v8：95 条真人零样本，全输入与只用掌姿，5 种子，配对 bootstrap；外加 v9 补记里的分类器检验像不像人。

v11（2026-10-07）：在线学习的两个改进，回答用户「在线学习还有没有提升空间」「输入历史 1 s、输出未来 1 s 加接触点，抓取策略是不是学得更快」。两个实验都用 v9 的逐次模拟（95 条真人按录制顺序先测后学，前 43 条调参、后 52 条留出），改两处：调参目标改为 pilot 上 1.0、0.5、0 s 三个时刻的误差各除以验收线再平均（v9 只看 1.0 + 0.5 s，选中了抬离时刻差于保持的线性修正）；另加一条流——52 条 formal 单独从基座开始学，前 20 次完全没参与调参，用来量「学得快不快」。① 多任务输出：4 种零真人基座（只用 gd_free、只用掌姿，配方同 v9 基座，各 4 个种子）——只学终点（对照）、加未来 1 s 掌姿（20 帧，相对当前帧；用输入流自己的未来，现场永远拿得到）、加拇指／食指接触点（物体系）、两个都加；在线学习的损失带同样的辅助项，另有一臂用「两个都加」的基座但在线只学终点；每臂同一个 9 点网格（学习率 × 步数）各自调参。② 线性修正 + 全网络微调（v9 基座）：按剩余距离加权——预测 = w·线性修正 + (1−w)·微调，w = min(1, 微调模型预测的剩余掌心位移 / r0)，r0 在 pilot 上选；恒 0.5 平均；叠加（每次微调后在微调模型自己的残差上再拟合线性修正）。另把这些方法在 ① 的 4 个对照基座上重跑一遍，看是不是只对一个基座有效。判据：留出段与「formal 单独开始」前 20 次的掌心误差、对微调（或对照）的逐 trial 配对 bootstrap、种子间方向是否一致、过线次数。测不了的：95 条全是成功、都有抬离标签，「未来轨迹不需要标签，掉落和两次抓取之间的运动也能学」要现场数据。同日晚，用户要求现场试「输出加未来 1 s」，理由是数据量大时数据效率更高：现场版 --online ft_fut 让成功抓取学终点 + 未来 1 s，其余运动（掉落、没有结果、从没抬起的试次，以及有标签 3 s 之前的接近）只学未来 1 s，每段运动存盘、续学跨 session 累积，操纵台一键启动；判据 = 现场逐次误差（学之前打分）+ 事后在同一份存盘运动上离线对比三种学法。

两个方案，不是同一个方法

共同输入是 Quest／L20 手部历史；主要差别是未来输出如何表示和生成
方案模型核心输出主要问题
A · No-Gaze Gaze-GuidedVQ-VAE motion codebook + decoder-only autoregressive Transformer一条从当前时刻到接触的未来 L20 手部序列离散 motion token 能否用少量动作前缀逐步续写完整动作？
B · Conditional Flow Matching条件速度场把高斯噪声连续运输到手姿分布多个可能的最终 L20 手姿候选；成立后再扩展短轨迹同一早期动作有多种可能时，能否减少确定性回归的平均化？

方案 A 更贴近 Gaze-Guided 3D Hand Motion Prediction 的原始结构，但删除其 gaze 和物体 embedding；方案 B 参考 Diffusion Policy 的条件生成思想，首个实现选择 Flow Matching 的连续速度场目标。Diffusion 与 Flow Matching 属于同一条“生成分布”路线的两种训练形式，本轮不把两者都各训一遍。

Flow Matching／DP 与 IL 的关系

Diffusion Policy把机器人观测作为条件、专家示范的未来动作作为输出，用离线 demonstration 做生成式 behavior cloning；在这种用法下，它属于 offline imitation learning。Diffusion 与 Flow Matching 本身只是学习条件数据分布的生成方法，并不天然等于 IL。

robot DP: observation → future robot action chunk → receding-horizon execution
Stage 1.2 A: past hand state → future hand-motion token sequence → decoded hand sequence
Stage 1.2 B: past hand state + noise → final intended hand-pose candidates → shadow-hand evaluation

Stage 1.2 的数据管线与 behavior cloning 相似，但输出是预测目标，不是要立即执行的 action，因此当前应称为监督式 Human Model。之后如果把候选经过 retargeting、几何修正与安全仲裁转成实时动作，才形成机器人 policy／shared-control 闭环。

两个方案共享什么数据？

单一 cube 消除了目标类别识别，不消除坐标问题。cube 固定时，每个 session 标定一次 T_world_object；所有手掌位置和方向都变换到 cube 坐标系。模型不输入 RGB、mesh、类别或 gaze，系统只在预处理和几何检查时使用已知 cube pose。

condition ct = past 1 s of [pOH(3), ROH(6), qL20,ref(16), valid(1)]
scheme A target Yt:T = future L20 hand-state sequence until confirmed contact
scheme B target y = final confirmed [pOP,T(3), ROP,T(6), qT(16)]

O 是 cube，H 是 Quest 人手掌，P 是 L20 掌。原始数据保留全频率、双时间戳、Quest 关节点和 tracking validity；窗口与26维派生输入只由训练代码生成。归一化统计只能从144条训练 trial 计算，48条 validation 和48条 test 不参与。

方案 A：No-Gaze VQ-VAE＋自回归 Transformer

完整 L20 手部运动序列 Y
↓ temporal encoder 压缩并匹配最近 codebook 向量
离散 motion tokens SVQ-VAE 学习动作词典并重建原序列
↓ 用历史 tokens 预测下一个 token
decoder-only Transformermasked self-attention + next-token cross-entropy
↓ 自回归生成未来 tokens
VQ-VAE decoder → 一条未来 L20 手部序列

第一步单独训练 VQ-VAE，loss 由动作重建、codebook embedding 和 commitment 三部分组成；第二步用训练好的 codebook 把动作变成离散 token，再训练 Transformer 的 next-token 分类，并提高终点 token 的权重。Quest 适配版不输入 gaze、RGB 或 object embedding，固定 cube 只通过物体坐标变换进入预处理。

该方案应先报告 VQ-VAE 自身重建误差、codebook 使用率和 collapse，再报告自回归未来序列的 ADE／终点误差；否则无法区分“动作压缩失败”和“Transformer 预测失败”。原论文通过 gaze 改善早期预测，删除 gaze 后预期会损失一部分提前辨别能力，必须作为本项目消融结果重新验证，不能沿用论文结论。

方案 B：状态条件 Flow Matching

历史手部状态 c + 真实最终抓姿 y
↓ 采样 ε ~ N(0,I)、τ ~ U(0,1)
xτ = (1−τ)ε + τy噪声到真实抓姿的直线路径
↓ 小型 MLP／TCN 接收 (xτ, τ, c)
vθ(xτ, τ, c)预测沿路径移动的速度
↓ 回归目标速度 u* = y − ε
LFM = ‖vθ − u*‖²

位置、6D rotation 和16个主动关节先分别按训练集尺度归一化，再拼成25维目标，避免单位差异让某一组变量支配 loss。首轮条件编码器保持小型，不加图像 backbone、VLM、object encoder 或 online update。Flow Matching的原始方法见 Lipman 等（ICLR 2023）；机器人 action 生成的对照见 Diffusion Policy（Chi 等，RSS 2023）。

方案 B 怎样得到多个候选？

当前1秒历史 c
↓ 采样多个独立噪声 ε₁…εₖ
积分 dx/dτ = vθ(x,τ,c)
↓ τ: 0 → 1
k 个最终 L20 抓姿候选
↓ FK、关节限位、穿透与候选去重
影子手可视化与离线评分

首轮不让候选修改用户命令。Flow Matching生成多个样本不等于自动知道哪个最好；best-of-k 只能衡量分布是否覆盖真实答案，不能冒充部署时的 top-1 性能。实际接入前还需要独立的候选排序、置信度校准和退让规则。

固定对照与继续判据

所有模型使用 Stage 1.1 冻结的相同 session 划分
模型输出回答的问题
B0 · 当前姿态保持把当前手姿当最终抓姿学习模型是否真的提前？
B1 · 最近示教检索一个训练集抓姿模型是否优于直接记忆示教？
M0 · 历史 MLP一个连续最终抓姿小数据下确定性回归能做到什么？

共同测试报告最终掌部平移误差、旋转角误差、主动关节误差和 FK 指尖误差；A 额外报告序列 ADE、VQ 重建误差与 codebook 使用率，B 额外报告几何无效率、top-1、best-of-k 和候选多样性。所有结果按 pinch／tripod／power grasp、方向、cube 位置与 session 分层。

A 与 B 都必须先超过 B0／B1 并与 M0 比较。A 若 codebook collapse 或序列终点不优于 M0，先停在确定性基线；B 若只增加样本抖动、无效姿态或训练集记忆，而没有改善模式覆盖，也保留 M0。不因“生成模型更新”而继续加大模型。

240条单用户 trial 只能支持 PoC，不能声称跨用户或跨物体。测试前依据 validation 固定候选数、筛选规则与误差容差；不预先写死提升阈值，首个 run 后按真实分布和下游误差需求登记。

进入 Stage 1.2 后只做这五步

  1. 读取并复核冻结数据。验证 manifest、session split、坐标重算、normalizer 与排除原因；不改 Stage 1.1 原始数据。
  2. 先跑 B0、B1、M0。得到确定性误差、提前量和平均手形失败样例，作为是否需要生成模型的事实依据。
  3. 训练方案 A。先验收 VQ-VAE 重建与 codebook，再训练无 gaze 的自回归 Transformer；保存未来序列与终点结果。
  4. 训练方案 B。使用相同历史条件和最终标签训练 Flow Matching；保存多个候选、几何过滤结果和推理耗时。
  5. 冻结评测并记录。共同比较终点指标，再分别报告 A 的序列质量和 B 的分布覆盖；决定保留 M0、A、B，或先补数据。
本阶段不做：不训练直接电机 action policy，不在线更新模型，不把 Flow Matching 候选直接送给真实机器人，不把“覆盖到真实姿态”解释成抓取稳定、承重或 pick 成功。
