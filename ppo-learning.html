§ 2问题本体：MDP、Observation，以及 episode 的两种结束

一个有限时域任务至少要交代状态、动作、动力学、奖励、初始分布和时域；学习器还要明确折扣 convention。这里刻意区分未折扣任务评价目标与 critic/GAE 使用的折扣回报：

$$\mathcal M_T=(\mathcal S,\mathcal A,P,R,\rho_0,T),\qquad J_{\mathrm{task}}(\theta)=\mathbb E\!\left[\sum_{t=0}^{T-1}r_t\right],$$ $$G_t^{(\gamma)}=\sum_{\ell=0}^{T-t-1}\gamma^\ell r_{t+\ell}.$$
Markov 性要求：给定当前 state 后，下一状态、奖励与结束信号的分布不再依赖更早历史。期望同时来自初始状态 $\rho_0$、随机策略 $\pi_\theta(a_t\mid o_t)$ 和环境动力学 $P$。真实机器人常只能看到 observation $o_t$，未必拥有满足这一条件的完整 state $s_t$；这时更准确的模型是 POMDP。
两个都叫“目标”的 convention 不要混。也可以把数学目标定义成 $J_\gamma=\mathbb E[\sum_t\gamma^t r_t]$；此时从固定初始分布推导出的精确策略梯度带外层 $\gamma^t$。常见 episodic PPO 以未折扣 episode return/success 评价策略，却在 value 与 GAE 内取 $\gamma<1$ 来控制估计方差，因此相对 $J_{\mathrm{task}}$ 引入了可控偏差。§6 会把两种写法并列。
terminated：MDP 真正结束

按任务定义，成功、失败、碰撞或吸收状态使未来回报不存在。target 中应令后继价值为 0；同一事件若环境没有定义为 terminal，就不能只凭名字擅自断开。

机械手例：物体掉出工作区，任务定义明确结束。

truncated：环境被外部边界截断

Gymnasium 的外部 time limit 等条件结束了 episode 记录，但底层状态仍可能有未来。通常要用该 transition 真正的 terminal observation 做 value bootstrap。

机械手例：达到 wrapper 的 500 步限制，但手还握着物体。

关键边界：time-limit truncation 应从该 transition 真正的 terminal observation 计算 bootstrap value；但是 GAE 的递推不能跨过环境 reset，把新 episode 的状态接到旧 episode 后面。学习器自己固定长度的 rollout boundary 则不是环境返回的 truncated=True，但片段末端同样通常要 bootstrap。也就是说，“是否 bootstrap”与“trace 是否继续”是两张不同的 mask。

如果固定时域本来就是任务定义的一部分，剩余时间应进入 state/observation，时域末端属于 termination；只有 MDP 外部的时间限制才是 truncation。实际字段名还取决于 Gymnasium 版本和 vector-env 的 autoreset mode，应读取对应的 terminal observation，而不是把某个旧字段名写死。

§ 3估计支流：从 Return 到 Value、Q 与 Advantage

策略梯度需要知道一次动作应该被鼓励还是压低。最原始的 REINFORCE 直接用整段采样回报；Actor-Critic 则学习一个 critic，把“动作好不好”改写成相对当前状态平均水平的优势：

$$V_\gamma^\pi(s)=\mathbb E_\pi[G_t^{(\gamma)}\mid s_t=s],\qquad Q_\gamma^\pi(s,a)=\mathbb E_\pi[G_t^{(\gamma)}\mid s_t=s,a_t=a],$$ $$A_\gamma^\pi(s,a)=Q_\gamma^\pi(s,a)-V_\gamma^\pi(s).$$
后文在不歧义时省略 $\gamma$ 下标。$A>0$ 不是“动作有正奖励”，而是它比该状态下策略通常会做的动作更好；$A<0$ 表示更差。减去只依赖 state 的 baseline 不改变对应策略梯度的期望，却能显著降低方差。

3.1 Bellman → TD → Q-learning：策略梯度之外的另一条活支线

$$V^\pi(s)=\mathbb E_\pi[r_t+\gamma V^\pi(s_{t+1})\mid s_t=s],$$ $$Q(s_t,a_t)\leftarrow Q(s_t,a_t)+\alpha\Big[r_t+\gamma\max_{a'}Q(s_{t+1},a')-Q(s_t,a_t)\Big].$$
Bellman 把长期回报拆成“一步奖励 + 剩余价值”；TD 用样本和 bootstrap 逼近这个递归；Q-learning 再用 greedy target 做 off-policy control。SARSA 则用当前行为策略实际选择的下一动作，是 on-policy control。

DQN 用神经网络表示 $Q$，再加入 replay buffer 与 target network 缓解相关数据和移动 target。它在离散动作上非常重要，但连续机械手动作里 $\arg\max_aQ(s,a)$ 难算，随机策略也不自然；这正是“直接参数化 policy”支流的动机，而不是说 policy gradient 淘汰了 Q-learning。

§ 4交互：$\gamma$ 不是“耐心”两个字，它决定有效时间尺度

折扣会让 $t$ 步后的奖励乘上 $\gamma^t$。常用直觉尺度是软时域 $H_{\mathrm{eff}}\approx1/(1-\gamma)$；半衰期是 $\log(0.5)/\log\gamma$。这不是 episode 的硬长度，却能告诉你远期信用还剩多少。

$\gamma=1$ 不是永远错误。有限、保证结束的 episodic task 可以使用 1；无限时域 discounted formulation 通常要求 $\gamma<1$ 才有有限回报。更重要的是让 $\gamma$ 与控制频率配套：同样的 0.99，在 10 Hz 与 100 Hz 下代表完全不同的物理时间。

§ 5GAE：把许多个 n-step Advantage 叠成一条可调光谱

先定义 TD residual：

$$\delta_t^V=r_t+\gamma\,m^{\mathrm{boot}}_t V_\phi(s_{t+1})-V_\phi(s_t),$$ $$\hat A_t^{\mathrm{GAE}(\gamma,\lambda)} =\delta_t^V+\gamma\lambda m^{\mathrm{trace}}_t\delta_{t+1}^V +(\gamma\lambda)^2m^{\mathrm{trace}}_tm^{\mathrm{trace}}_{t+1}\delta_{t+2}^V+\cdots.$$
$m^{\mathrm{boot}}$ 决定末端 value 是否为 0；$m^{\mathrm{trace}}$ 决定递推能否接到下一条 transition。真正 termination 两者都断；time-limit truncation 通常 bootstrap，但 trace 在 reset 处必须断。
实践起点：$\gamma=0.99,\lambda=0.95$ 只是常见起点，不是 PPO 定义的一部分。短回合、稀疏远期奖励、高控制频率或 critic 明显欠拟合时，都应重新检查这两个时间尺度。

§ 6策略梯度支流：从 REINFORCE 到 Actor-Critic

策略 $\pi_\theta$ 诱导整条轨迹的概率。利用 log-derivative trick，环境动力学不需要可微。先采用严格的 discounted-start objective $J_\gamma$：

$$p_\theta(\tau)=\rho_0(s_0)\prod_t\pi_\theta(a_t\mid s_t)P(s_{t+1},r_t\mid s_t,a_t),$$ $$\nabla_\theta p_\theta(\tau)=p_\theta(\tau)\nabla_\theta\log p_\theta(\tau),\qquad \nabla_\theta\log p_\theta(\tau)=\sum_t\nabla_\theta\log\pi_\theta(a_t\mid s_t),$$ $$\nabla_\theta J_\gamma(\theta) =\mathbb E_{\tau\sim\pi_\theta}\!\left[ \sum_t \gamma^t\nabla_\theta\log\pi_\theta(a_t\mid s_t)\,A_\gamma^\pi(s_t,a_t) \right],\qquad \hat g_{\mathrm{rollout}}=\hat{\mathbb E}_t[\nabla_\theta\log\pi_\theta(a_t\mid s_t)\hat A_t].$$
左式是固定初始分布、discounted objective 的精确形式；右式是普通 PPO 固定长度 rollout 常用的实践 surrogate，它对时间样本做均匀平均且不再额外乘 $\gamma^t$，一般不等于同一个 $J_\gamma$ 的无偏梯度。只有显式按 discounted occupancy $d_\gamma^\pi$ 采样/加权时，两种写法才可严格对应。对未折扣 episodic 目标而 $\gamma<1$ 的常见 GAE 实现，也应坦白把 $\gamma$ 当作降低方差的偏差旋钮。环境转移项不依赖 $\theta$，所以从 log-gradient 中消失，但仍通过采样轨迹进入期望。

REINFORCE 用 reward-to-go $G_t$。减去任何不依赖当前动作的 state baseline 不会改变期望梯度：

$$\mathbb E_{a\sim\pi_\theta}\!\left[b(s)\nabla_\theta\log\pi_\theta(a\mid s)\right] =b(s)\nabla_\theta\sum_a\pi_\theta(a\mid s)=0.$$
令 $b(s)\approx V^\pi(s)$，就从 $G_t$ 得到 advantage 估计。连续动作时求和换成积分，结论相同；baseline 若依赖当前 action，则不能直接套用这个无偏证明。

一步 Actor-Critic 再用 TD residual 近似 advantage，同时训练 critic：

$$\delta_t=r_t+\gamma m_t^{\mathrm{boot}}V_\phi(s_{t+1})-V_\phi(s_t),$$ $$\theta\leftarrow\theta+\alpha_\pi\operatorname{stopgrad}(\delta_t)\nabla_\theta\log\pi_\theta(a_t\mid s_t),\qquad \phi\leftarrow\phi+\alpha_V\operatorname{stopgrad}(\delta_t)\nabla_\phi V_\phi(s_t).$$
这里把 TD target / residual 对 critic 视为固定目标；否则梯度会穿过 $V(s_{t+1})$，变成另一种 residual-gradient 算法。true termination 时 $m^{\mathrm{boot}}=0$；外部 truncation 通常为 1。
REINFORCE 解决什么

无需动作价值的 argmax，天然支持随机策略与连续动作；只要能采样轨迹，就能给 policy 一个无模型梯度。

它为什么抖

一次完整回报混入了环境随机性和许多无关未来事件；同一状态的梯度方向在不同 episode 间可能相反。

Baseline / Critic 修什么

减去 $V(s)$ 只保留“比平常好多少”；TD bootstrap 让每个片段不必等到 episode 结束。

新的问题

估计器有 bias，且一次大梯度步会让新策略远离产生数据的旧策略，旧 Advantage 立刻失真。

6.1 第三支流：A3C/A2C 改的是采样与更新组织方式

Actor-Critic 在数学上已经把价值支流与策略梯度支流接起来；但单环境在线更新仍然慢、样本相关性强。A3C 让多个 worker 异步采样并把梯度推到共享参数，借并发打散相关性；同步版本 A2C 等所有 worker 走完同样长度再组成一个大 batch，更容易用向量化环境和加速器做稠密计算。

Online Actor-Critic、A3C、A2C 与 PPO 的数据和更新节奏比较
系统数据/更新节奏带来的东西留下的问题
Online Actor-Critic少量 transition 就更新反馈快、概念直接相关性强、硬件利用率低

谱系关系：PPO 不是“A2C 的下一代公式”。A2C/A3C 提供的是并行 Actor-Critic 的系统形状；GAE 提供优势估计；TRPO 提供 proximal update 的问题意识。PPO 把这三件事装进同一训练循环。

最后一个问题就是信任域支流的入口。我们希望复用旧策略采到的数据，于是引入 importance ratio：

$$r_t(\theta)=\frac{\pi_\theta(a_t\mid s_t)}{\pi_{\theta_{\mathrm{old}}}(a_t\mid s_t)} =\exp\left(\log\pi_\theta-\log\pi_{\theta_{\mathrm{old}}}\right),$$ $$L^{\mathrm{sur}}(\theta)=\mathbb E_t[r_t(\theta)\hat A_t].$$
更新开始时 $r=1$。这个逐步 ratio 只校正旧状态下所选 action 的 likelihood，没有校正新旧策略的 state-visitation distribution；所以它是局部 surrogate，不是 $J(\pi_{\mathrm{new}})$ 的无偏 off-policy 估计。若在同一批数据上反复优化，$r$ 会离 1 越来越远，“旧策略采样 + 旧 Advantage”也越来越不可信。这正是 PPO 只做有限 epochs、随后必须重新 rollout 而不能把旧批次当 replay buffer 的原因。

6.2 Natural Policy Gradient：参数空间的同样一步，并不代表策略变得同样多

普通梯度按参数的欧氏距离量步长，但同一个策略可有不同参数化，而且某些参数方向会让动作分布改变得特别快。Natural gradient 用策略分布的 Fisher 几何修正方向：

$$\Delta\theta_{\mathrm{nat}}\propto F^{-1}g,\qquad F=\mathbb E[\nabla_\theta\log\pi_\theta\,\nabla_\theta\log\pi_\theta^\top].$$
这一步把“参数走多远”改成“policy distribution 变多少”。TRPO 随后把这个局部几何明确写成 KL trust region，并加入求解与 line search。

§ 7TRPO：把“别走太远”写成 KL 约束

TRPO 最大化 surrogate，同时把新旧策略的平均 KL 限在 $\delta$ 内。它用 Fisher 信息矩阵的二次近似构成局部 trust region，再用共轭梯度与 line search 求一个可接受步长：

$$\max_\theta\ \hat{\mathbb E}_t[r_t(\theta)\hat A_t] \quad\text{s.t.}\quad \hat{\mathbb E}_t[D_{\mathrm{KL}}(\pi_{\theta_{\mathrm{old}}}\Vert\pi_\theta)]\le\delta.$$
理论分析提供了与策略改进有关的下界，但实际 TRPO 使用采样均值、局部二阶近似和 line search。它比裸梯度稳健，不应被描述成“任何函数逼近和有限样本下都无条件单调提升”。
TRPO 的瓶颈不是理念，而是求解器。Hessian-vector product、共轭梯度、阻尼和 line search 增加了实现与调试成本。PPO 的目标是用普通一阶 optimizer 得到相似的“小心更新”行为。

§ 8PPO：Penalty 与 Clip，到底限制了什么

8.1 PPO-Penalty：把约束移进目标

$$L^{\mathrm{KLPEN}}(\theta) =\hat{\mathbb E}_t\!\left[r_t(\theta)\hat A_t-\beta D_{\mathrm{KL}}(\pi_{\mathrm{old}}\Vert\pi_\theta)\right].$$
若实际 KL 太大就增大 $\beta$，太小就减小。它保留“距离”的直接含义，但自适应 penalty 的反馈速度和尺度会影响训练。

原论文给出的简单反馈规则是：若测得的 KL 小于目标的 $1/1.5$，令 $\beta\leftarrow\beta/2$；若大于目标的 $1.5$ 倍，令 $\beta\leftarrow2\beta$。论文实验中 adaptive penalty 不如 clipped objective，但它最直接地保留了“软 KL 弹簧”的解释。

8.2 PPO-Clip：对“会继续改善样本目标的过大 ratio”截平收益

$$\ell_t^{\mathrm{CLIP}}(\theta)= \min\Big(r_t\hat A_t,\ \mathrm{clip}(r_t,1-\epsilon,1+\epsilon)\hat A_t\Big) ,\qquad L^{\mathrm{CLIP}}(\theta)=\hat{\mathbb E}_t[\ell_t^{\mathrm{CLIP}}(\theta)].$$

分段读法最清楚：若 $\hat A_t\ge0$，样本项是 $\min(r_t,1+\epsilon)\hat A_t$；若 $\hat A_t<0$，样本项是 $\max(r_t,1-\epsilon)\hat A_t$。

PPO Clip 在正负 Advantage 与六种 ratio 区域下的逐样本结果
Advantageratio 区域最终样本项是否平台

三件不能说错的事。
  1. Clip 没有把网络产生的 ratio 硬限制在 $[1-\epsilon,1+\epsilon]$；它只让特定方向上的样本目标变平。
  2. $L^{\mathrm{CLIP}}$ 是未裁 surrogate 的逐样本悲观下界，不是环境真实 return 的严格下界。
  3. Clip 不等价于 TRPO 的 KL 约束。ratio 仍可能漂很远，所以实际实现常监控 approximate KL，并可在超过 target KL 时提前停止本轮 epochs。

§ 9完整 PPO loss：Policy、Value、Entropy 各负其责

论文常写“最大化”的目标，代码通常写“最小化”的 loss。以下采用最小化约定：

$$\mathcal L(\theta,\phi)= -\underbrace{\mathbb E[\ell_t^{\mathrm{CLIP}}(\theta)]}_{\text{policy}} +c_v\underbrace{\mathbb E\!\left[\tfrac12(V_\phi(s_t)-\hat R_t)^2\right]}_{\text{value}} -c_e\underbrace{\mathbb E[\mathcal H(\pi_\theta(\cdot\mid s_t))]}_{\text{entropy}}.$$
Policy 学动作偏好；value 回归 $\hat R_t=\hat A_t+V_{\mathrm{old}}(s_t)$；entropy 奖励分布保持一定随机性。共享 backbone 时三项梯度会在特征层相互作用。
完整 PPO loss 的核心组件与常见误区
组件必须/可选常见误区
PPO clipped policy objectivePPO-Clip 核心用更新后的 log-prob 覆盖 buffer 里的 logp_old，导致 ratio 永远接近 1
Value regressionActor-Critic PPO 必需truncation 当 termination，使 critic 系统性低估末端
Entropy bonus常用但系数可为 0只看 entropy 数字，不看动作尺度、log_std 与是否饱和
Value clipping工程选项误称 PPO 数学定义；它可能稳住更新，也可能阻碍 critic 追 target
Advantage normalization工程选项有助优化尺度，但会改变 batch 内样本相对权重，不是无条件理论要求
Reward/return scaling工程选项一边缩放 reward，一边沿用未缩放的 value/阈值解释
Value clipping 的典型写法：比较未裁新 value 与围绕 $V_{\mathrm{old}}$ 裁剪后的 value，各自对同一 return target 的平方误差，再取较大者。它模仿 policy clip 的“悲观”形式，但不同库的开关与细节并不统一，复现实验必须逐项核对。

§ 10完整数据循环：一批 on-policy 数据的一生

PPO 的工程本体不是一条公式，而是一条严格的数据生命周期。点击各阶段或自动播放：

10.1 Buffer 至少保存什么

PPO rollout buffer 建议保存的字段及用途

10.2 固定长度 rollout 不等于完整 trajectory

$N$ 个环境各采 $T$ 步得到 $N\times T$ transitions；绝大多数片段会在 episode 中间结束，因此最后一个状态通常要 bootstrap。若 vector env 自动 reset，要依据当前库版本和 autoreset mode 取出真正的 terminal observation（不同版本可能使用普通终止步 obs、final_obs 等约定）。随后按时间反向递推 GAE，把数据 flatten、shuffle 成 minibatch，执行 $K$ 个 epochs。每个 minibatch 都用同一份 frozen logp_old，但重新计算当前 logp_new、entropy 与 value。

§ 11连续动作 PPO：Gaussian 只是起点，边界与 log-prob 必须一致

机器人控制常用对角高斯：

$$\pi_\theta(a\mid s)=\mathcal N\!\left(\mu_\theta(s),\operatorname{diag}(\sigma_\theta^2(s))\right),\qquad \log\pi(a\mid s)=\sum_i\log\mathcal N(a_i;\mu_i,\sigma_i^2).$$
连续动作下这里是概率密度；joint log-prob 必须对动作维求和而非平均。log_std 可以是全局可训练向量，也可以由网络随 state 输出；两者都是设计选择。对角协方差忽略动作维之间的显式相关，但共享网络仍让均值依赖同一 observation。
方案 A · Sample 后 clip

实现简单，但环境执行的是裁后动作，log-prob 往往针对裁前样本；边界处产生概率质量堆积与梯度语义偏差。要监控 saturation。

方案 B · Tanh-squashed Normal

$u\sim\mathcal N,\ a=\tanh u$，再缩放到动作范围。log-prob 必须包含 change-of-variables 修正 $\sum\log(1-\tanh^2u)$。

方案 C · 有界分布

如 Beta policy 原生定义在有限区间，但参数化、数值稳定与成熟实现生态不同。不是所有 PPO 库都直接支持。

# tanh-squashed Gaussian：old/new log-prob 必须采用同一变换约定
u      = Normal(mu, std).sample()
a_unit = tanh(u)
scale  = 0.5 * (high - low)
action = low + (a_unit + 1) * scale
logp   = Normal(mu, std).log_prob(u).sum(-1)
logp  -= stable_log_one_minus_tanh_sq(u).sum(-1)
logp  -= log(scale).sum(-1)                  # 映射到环境动作单位

优先使用框架经过数值稳定处理的 TanhTransform / transformed distribution；直接算 log(1-tanh(u)^2) 会在饱和区下溢。若 old/new policy 使用完全相同、固定的线性动作 scale，这个常数项会在 log-prob 差里抵消；但要报告正确的绝对 density/entropy，或比较不同变换时，仍应把它写清楚。仅用未 squash Normal 的解析 entropy 也不等于 squashed policy 的精确 entropy。

多轮 PPO 更新时若只保存环境动作，重算新 log-prob 必须先撤销 affine scale，再用数值保护的 atanh 还原 latent $u$；更稳妥的实现是保存 pre-tanh $u$，或让 transformed distribution 统一完成正反变换。把有界环境 action 直接传给 base Normal 的 log_prob 是错误的。

  • 训练通常随机采样；评估常用 latent mean 的确定性变换动作（squashed policy 为 $\tanh\mu$ 再缩放）。它一般不等于 transformed distribution 的数学期望 $\mathbb E[\tanh U]$。评估应固定种子并报告多 episode 分布，而非只挑最好视频。
  • Observation normalization 的统计量在训练与评估必须一致；部署时冻结或显式更新，不能悄悄重置。
  • 动作单位、scale、控制频率与 action repeat 会改变同一个 policy output 的物理含义，也会改变 $\gamma$ 对应的秒数。
  • 若 actuator 有耦合、速率或安全约束，仅靠独立高斯和 clip 可能不够；可考虑结构化 policy、projection 或 constrained RL。

§ 12诊断：不要只盯 episodic return

PPO 训练诊断指标、含义与危险信号
指标它回答什么危险信号
Return / success rate任务最终有没有变好reward 上升而成功率不升：reward hacking 或 shaping 代理错位
Approx KL新旧策略实际移动多远突然尖峰；连续远超 target；clip 仍无法阻止漂移
Clip fraction多少样本的 ratio 跑出 $[1-\epsilon,1+\epsilon]$；标准定义不等于“真正被 min 裁平”的符号相关比例长期接近 0：步太小；长期很高：epoch/LR 太激进或优势尺度异常
Entropy / log_std探索分布是否塌缩或爆开过早趋近极低；某些 action 维 std 爆炸
Explained variancecritic 是否解释 return target 变化接近 0：几乎没学；显著负值：比常数预测还差
Value loss / value scalecritic target 与预测是否匹配reward scale 改后突然爆炸；value clipping 长期饱和
Gradient norm优化是否数值稳定频繁碰 max-grad-norm；NaN 前持续抬升
Action saturationpolicy 是否长期撞边界大量动作等于上下限，mean/std 与环境执行动作脱节
$$\widehat{D}_{\mathrm{KL}}\approx\mathbb E[\log\pi_{\mathrm{old}}-\log\pi_{\mathrm{new}}], \qquad \mathrm{clipfrac}=\mathbb E[\mathbf 1(|r_t-1|>\epsilon)],$$ $$\widehat{D}_{\mathrm{KL}}^{\mathrm{nonneg}}\approx \mathbb E[(r_t-1)-\log r_t],$$ $$\mathrm{ExplainedVariance}=1-\frac{\mathrm{Var}(\hat R-V)}{\mathrm{Var}(\hat R)}.$$
第一种 KL 估计简单但在有限 minibatch 上可能出现小负值；第二种逐样本非负、常用于诊断。若 $\mathrm{Var}(\hat R)=0$，explained variance 没有定义，不能据此判断 critic。
症状：return 突然掉崖，approx KL 与 clip fraction 同时暴涨

先查 learning rate、epochs、minibatch size、advantage 尺度与 old log-prob 是否冻结；再查 observation normalization 是否跳变。临时降低 LR/epochs 可以止血，但必须找到尺度或数据 bug。

症状：return 不动，entropy 很快归零

策略过早确定化。检查 entropy coefficient、初始 log_std、动作是否大量 clamp、reward 是否让一个静止姿势轻易吃到稳定分，以及 reset 随机性是否足够。

症状：value loss 很漂亮，policy 却不进步

critic 可能只是在拟合容易的 dense shaping；检查 Advantage 的均值/标准差、符号与 mask，成功事件是否在有效时域内，以及 policy gradient 是否被错误 detach 或 ratio 恒为 1。

症状：训练很好，deterministic eval 很差

检查训练时是否依赖极大随机 std、评估是否使用了错误的 normalization、latent mean 的确定性动作是否漏做 tanh/scale，以及训练环境的 domain randomization 是否覆盖评估条件。

§ 13PPO 的优劣势，以及什么时候不要用它

为什么 PPO 成熟、好用
  • 一阶优化，结构简单，容易与 CNN/RNN/Transformer policy 结合。
  • 向量环境吞吐友好；固定 rollout、GAE 和 minibatch 很适合 GPU。
  • 比裸 policy gradient/A2C 的多 epoch 更新更稳健，诊断指标成熟。
  • 同时支持离散和连续动作，是模拟控制的强基线。
PPO 没解决什么
  • 本质仍是 on-policy：旧数据很快过期，真实交互样本效率通常不如 off-policy。
  • Clip 不是 trust-region 保证；超参、reward scale、网络与实现细节仍敏感。
  • 稀疏长时信用、部分可观测、强约束和离线数据不会因 PPO 自动消失。
  • 大规模并行能掩盖低样本效率，却不能让昂贵真实机器人交互变便宜。
不同强化学习任务情境的算法选择建议
情境优先考虑理由
模拟器便宜、可开很多并行环境PPO吞吐换稳定性；容易建立可靠 baseline
离散动作、想复用 replayDQN 系列off-policy value learning 与 replay 更自然
连续动作、真实交互昂贵SAC / TD3off-policy 数据复用，通常样本效率更高
要显式控制相邻 policy 的 KLTRPO实际求解仍是近似，但比 PPO clip 更直接表达 update trust region
存在任务成本或安全硬约束CPO / constrained RL / safety layerTRPO 的 policy-KL 也不等于碰撞、力矩或风险约束
有大量专家演示BC / Imitation，再按需 RL先利用监督信号，避免从零探索
动力学可学且每次交互极贵Model-based RL / MPC用模型规划或合成更多学习信号
长记忆、观测不充分Recurrent PPO 只是一个选项先确认 POMDP、hidden-state reset 与 sequence batching 正确

§ 14最小正确实现：伪代码、单元测试与复现清单

initialize actor theta, critic phi
for iteration in 1..M:
    snapshot theta_old and phi_old; clear rollout buffer
    for t in 1..T:
        action, logp_old = actor_old(obs)
        value_old = critic_old(obs)
        next_obs, reward, terminated, truncated, info = env.step(action)
        episode_boundary = terminated or truncated or explicit_manual_reset
        successor = terminal_obs_by_api_mode if episode_boundary else next_obs
        bootstrap_value = 0 if terminated else critic_old(successor)
        trace_mask = 0 if episode_boundary else 1
        store(obs, action, reward, logp_old, value_old,
              bootstrap_value, trace_mask, terminated, truncated)
        obs = next_control_observation_by_api_mode

    # Reverse time within each environment.
    # Each transition has its own successor value; this matters when an
    # auto-resetting env truncates in the middle of a rollout buffer.
    for env in vector_environments:
        advantage_next = 0
        for t in reversed(0..T-1):
            delta_t = reward_t + gamma*bootstrap_value_t - value_old_t
            advantage_t = delta_t + gamma*lambda*trace_mask_t*advantage_next
            advantage_next = advantage_t
    returns = advantage + value_old

    optionally normalize advantage using this rollout batch
    for epoch in 1..K:
        shuffle buffer into minibatches
        for batch in minibatches:
            logp_new, entropy, value_new = network(batch.obs, batch.action)
            A = batch.advantage.detach()
            ratio = exp(logp_new - batch.logp_old)  # old stays frozen
            clipped_ratio = clip(ratio, 1-epsilon, 1+epsilon)
            policy_loss = -mean(min(ratio*A, clipped_ratio*A))
            value_loss  = value_objective(value_new, batch.returns)
            loss = policy_loss + cv*value_loss - ce*mean(entropy)
            optimizer.zero_grad(); loss.backward()
            clip_gradient_norm(); optimizer.step()
        if approximate_KL > target_KL: break
测试 1 · 初始 ratio

更新前用同一参数重算，所有 $r$ 应接近 1；否则 old/new log-prob、action transform 或 batch 对齐有错。

测试 2 · GAE 小数组

用手算 3–5 步 residual，覆盖 terminated、truncated 与 rollout boundary，专门防 off-by-one。

测试 3 · Clip 分段

分别测试 $A>0,r>1+\epsilon$ 与 $A<0,r<1-\epsilon$ 的平坦区，以及反方向仍保留梯度。

测试 4 · Action log-prob

采样、缩放、tanh 与 Jacobian 修正必须能对同一 action 重算出一致 log-prob。

  • 记录代码版本、环境版本、wrapper 顺序、网络初始化、optimizer epsilon、所有 normalization 与 seed。
  • 至少多 seed 报告均值与离散程度；训练曲线同时画 environment steps 和 wall-clock。
  • 明确 episode return 是否包含终止奖励、是否跨 frame-skip、vector env 是否自动 reset。
  • 保留 success、KL、clipfrac、entropy、explained variance、value scale、gradient norm 与 action saturation。
  • 先用小环境过单元测试，再开 4096 环境；并行吞吐不能证明 transition 语义正确。
一页总结：critic/GAE 回答“这个动作相对平均有多好”；importance ratio 用旧状态上的动作概率构造局部新旧 surrogate；TRPO 用 KL 几何约束一步；PPO 用 penalty 或 clipped surrogate 把它改成一阶优化；A2C/A3C 的并行采样传统把上述零件组织成 rollout—minibatch 系统。PPO 的成熟来自这次汇合，而不是某一条神奇公式。
