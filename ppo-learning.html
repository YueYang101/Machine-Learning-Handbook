Stage 1 — MDP 与 RL 的基本问题

1. RL 到底和普通监督学习有什么不同？

监督学习

你通常直接拿到：

输入 x → 正确答案 y

模型输出 ŷ，直接和 y 算 loss。

强化学习

你通常只有：

状态 sₜ → 动作 aₜ → 环境变化 → 奖励 rₜ

没有人在每一步直接告诉你：“这个动作的正确答案是什么”。

所以 RL 的核心问题不是分类或回归，而是：

在一个会持续变化的环境中，应该选择什么动作，才能让未来累计获得的 reward 最大？

2. 为什么需要 MDP？

MDP，全名 Markov Decision Process，可以看成是对 RL 环境的一套数学描述。 最常见的写法是：

MDP = (S, A, P, R, γ)
符号 名称 它回答什么问题？
S State space 环境现在是什么状态？
A Action space Agent 可以做什么？
P Transition 做完动作以后，环境会怎么变化？
R Reward 这个结果好不好？
γ Discount factor 未来的 reward 要看多重？

3. State：sₜ 到底是什么？

sₜ 表示时间 t 时，Agent 用来决定动作的信息。

例如一个机械手抓取任务，state 可能包含：

sₜ = [ hand joint positions, hand joint velocities, object position, object orientation, target position ]

在纯 state-based 仿真里，它不一定需要图像。只要这些状态变量已经足够描述任务，就可以直接作为 policy 输入。

关键理解： State 不是“所有历史数据”，而是我们希望它已经包含了做下一步决策需要的信息。

4. Markov Property：为什么只看当前 state？

Markov property 的核心写法是：

P(sₜ₊₁ | s₀, a₀, s₁, a₁, ..., sₜ, aₜ) = P(sₜ₊₁ | sₜ, aₜ)

它并不是说“历史不存在”，而是说：

一旦当前状态 sₜ 已知，更早的历史信息就不应该再额外影响下一步状态的概率。

举个机械手例子：如果 sₜ 已经包含当前每个关节的位置、速度和物体姿态， 那么预测下一时刻时，理论上不需要再单独知道“1 秒前关节在哪里”。

5. Action：aₜ 是什么？

Policy 根据 state 选择 action：

sₜ → policy → aₜ

对于机器人，action 可能是：

  • joint torque
  • joint velocity command
  • joint position target
  • end-effector delta pose

例如：

aₜ = [τ₁, τ₂, τ₃, ..., τ₂₀]

表示 20 个关节的 torque command。

6. Transition：P(sₜ₊₁ | sₜ, aₜ)

这一项描述：

当前 sₜ + 执行动作 aₜ → 下一状态 sₜ₊₁

在 MuJoCo / Isaac Sim 中，这个 transition 很大一部分就是 physics engine 在帮你计算。

理论写法通常是：

P(sₜ₊₁ | sₜ, aₜ)

之所以写成概率，是因为真实环境中可能存在噪声和不确定性。

7. Reward：rₜ 到底是什么？

Reward 是环境给 Agent 的一个标量反馈：

rₜ = R(sₜ, aₜ, sₜ₊₁)

例如抓取任务：

rₜ = - distance(hand, object) + 10 × grasp_success + 50 × lift_success

注意：reward 不是“正确 action”。

Reward 只是在告诉 Agent：这个结果有多好。
它没有直接告诉 Agent：“下一步应该把第 3 个关节旋转 0.2 rad。”

8. Policy：π(a | s) 是什么？

Policy 是 RL 中真正负责“做决定”的东西。

π(a | s)

意思是：

在 state = s 的条件下，选择 action = a 的概率

对连续控制，常见做法不是直接输出唯一动作，而是输出一个概率分布，例如：

πθ(a | s) = Normal( μθ(s), σθ(s) )

然后：

aₜ ~ πθ(a | sₜ)

这就是后面 PPO 里面为什么会不断出现：

πθ(aₜ | sₜ) log πθ(aₜ | sₜ) πnew(aₜ | sₜ) / πold(aₜ | sₜ)
非常重要： PPO 优化的核心不是“把网络输出的动作直接和某个标准动作做 MSE”，而是改变这个 policy distribution， 让高 Advantage 的动作以后更容易被采到。

9. Trajectory：一次完整交互是什么？

从一个初始状态开始，不断：

s₀ → a₀ → r₀ → s₁ → a₁ → r₁ → s₂ → ...

这一整条序列叫 trajectory：

τ = (s₀, a₀, r₀, s₁, a₁, r₁, ..., s_T)

后面你看到的 rollout，本质上就是拿当前 policy 去环境里采 trajectory。

10. Return：为什么不能只看当前 reward？

假设机械手为了抓到物体，前 30 步都没有成功奖励，直到最后一步才：

r₃₀ = +100

那么前面的动作是不是完全没有价值？

当然不是。

所以 RL 不只看 rₜ，而看从这一刻开始的累计未来奖励：

Gₜ = rₜ + γ rₜ₊₁ + γ² rₜ₊₂ + γ³ rₜ₊₃ + ...

这个 Gₜ 就是 Return。

11. γ：Discount Factor 为什么存在？

0 ≤ γ ≤ 1

例如：

γ = 0.99

意味着未来 reward 会逐渐折扣。

Reward 时间 对当前 Gₜ 的权重
现在1
下一步γ
2 步以后γ²
100 步以后γ¹⁰⁰

γ 有两个作用：

  • 让更近的 reward 通常更重要；
  • 在无限时间问题中，让 return 更容易保持有限。

12. RL 真正优化的对象

现在我们终于可以写出强化学习最核心的目标：

找到一个 policy π， 让它产生的 trajectory 的期望 return 最大。

数学上可以先粗略写成：

maximize   J(π) = E[ G₀ ]

后面当 policy 由神经网络参数 θ 控制时，就会变成：

maximize   J(θ)

而这正是后面 Policy Gradient 要开始解决的问题：

既然我要让 J(θ) 变大，那我应该怎样对 θ 求梯度？

Stage 1 最后你应该真正掌握什么

Checkpoint 1
看到 sₜ, aₜ, rₜ, sₜ₊₁ 时，能够立即知道四者分别表示什么。
Checkpoint 2
能解释为什么 RL 没有每一步的标准答案，而只有 reward。
Checkpoint 3
能解释 reward 和 return 的区别： rₜ 是一步反馈，Gₜ 是未来累计回报。
Checkpoint 4
能解释 π(a|s) 是动作分布，而不是固定动作。
Checkpoint 5
知道 PPO 后面训练的最终目的仍然只有一个： 改变 policy，使期望 return 增大。
