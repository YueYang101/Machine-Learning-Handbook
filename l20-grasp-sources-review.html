§ 1三个入口成立，但并不互斥

H/G/O 是本项目的来源标签，不是论文互斥分类；B0–B3 留给持物 controller
入口输入 → 产物是否要训练最容易误解的地方
H：人手 / 人工模板人手关键点、手物位姿、接触／类型 → L20 reference，或直接在 L20 标注模板几何 retarget 不需要；物理 RL retarget 可能需要人工机器人模板不等于真实人类数据 retarget；几何相似不证明承重
G：生成模型物体几何 + 手描述／抓取条件 → 抓姿、接触或距离表示，再求 IK适配已支持本体可用权重；新手可能要重训生成的关节目标不是闭环控制策略，也不自带用户意图
O：数学 / 仿真优化手、物体、候选接触和初值 → 优化后的 grasp / squeeze通常不需要学习模型；需要优化计算force closure / QP 分数不是动态持物成功率

例如 Dexonomy 是人工类型模板 + 优化（H+O），GenDexGrasp 是神经接触图 + 优化（G+O），人类姿态经 BODex 修正属于 H+O。保留 source、retargeter、refiner 三个字段，不能一修正就把人类来源改成“纯优化”。

后续 robust grasp 的参考链路是：来源 → 统一 candidate → 固定闭合与承重检查 → 合格初态 → 同一持物 controller → 统一扰动评测。这是物理控制阶段的备忘，不是当前 Stage 1.1 的任务。

§ 3人类数据库：有，但保存的不是机器人控制命令

Zhan / Yang 等，CVPR 2024		双手长任务、物体状态、primitive 描述与依赖图长期 pick → use → place 分解、意图与局部技能接口官方页面仍注明 preview、标注可能更新；固定下载版本。当前单一 cube PoC 不依赖它

先把“一条数据”读通，不先建一个大数据库

  1. 登记许可、dataset version、subject / object / sequence / frame ID，取右手与对应物体 mesh；保留米／毫米、坐标系和 MANO 版本信息。
  2. 把手与物体变到同一 object frame；可视化掌面、拇指、关键点及接触。确认不是左手镜像错误或不匹配的物体尺度。
  3. 固定同一输入，对 angle、vector、DexPilot 分别输出 L20 reference；只调整训练／开发样本上的 mapping、scale 和约束。
  4. 导出物体相对掌位姿、主动关节目标、接触／类型标签。当前 PoC 检查几何合理性并配对用户输入；后续物理控制再参考统一合同做承重检查。保存失败样本，不仅留好看的。

70 mm cube 的特殊限制：不能把 ContactPose 的某个 bottle 抓姿缩一缩便声称是“原始人类方块示教”。第一轮 cube 的人类来源用本地采集或明确标记的人工 L20 模板；公共库接入先在它自己的匹配 mesh 上做一个独立 adapter 验收。若要把该物体纳入正式比较，建立新的 object manifest，三类来源都使用同一物体与尺度，不偷换当前 cube benchmark。

在人／物／序列层面先切分，再截帧、retarget 和增强。同一段视频的相邻帧、同一源抓姿的微扰不能横跨训练与测试。公开数据仅给先验，不给本项目的动力学真值。

R6 人类轨迹 → 生成式先验
Learning Continuous Grasping Function with a Dexterous Hand from Human Demonstrations
Ye 等，RA-L 2023		人类抓取轨迹 retarget 后学习连续 grasping function；属于 H → G 的组合作者页提供代码入口，演示以 Allegro 为主。用于后续自然 approach / closure，不能替代在线抗扰 controller
人类 style 到底保留什么？分三项报告：① 抓取类型／主动接触指与区域；② 手形几何误差、限位／穿透；③ 开合次序与运动平滑。阶段 1.1 首先保留①、记录②；③ 到完整 acquisition 才测试。低手姿误差、看着像人、真正承重是三项不同指标。

选型结论：用 已有 L20 vector + dex-retargeting 的目标函数对照启动；接触感知／物理 retarget 是在“几何已匹配但动力学仍失败”之后启用的升级。不得把复用 retarget 库理解为已经有部署抓取策略。

别把“模型生成抓姿”与“学一个抓取控制器”混在同一行

DexGrasp-Zero（Wu 等，2026）研究 morphology-aligned 跨本体控制策略，不是静态候选生成器。DemoGrasp（Yuan 等，ICLR 2026）提供单示教引导训练和数据收集路径；RobustDexGrasp（Zhang 等，CoRL 2025）是鲁棒执行／观测迁移参考。它们应放在 controller / acquisition 分支评估，不作为 G-DRO 的同类静态采样器。官方支持手、仿真引擎和权重种类不匹配时，不承诺 L20 即用。

因此“是否用现成模型”的回答是：能匹配本体与输入合同的现成生成器就复用；当前先不用新训生成器。持物 residual 是独立训练项。生成器只要通过合同，后续更换时不改 reward 和 controller 接口；但更换 candidate bank 后必须重新验证策略分布兼容性。

Chen / Ke / Peng / Wang，RSS 2025		每手、每抓取类型人工模板 + 接触与模拟优化；直接连接“像人／类型”与物理可行性MuJoCo 代码、数据与模板入口；支持列表含 Shadow / Allegro / LEAP / MANO / G1，不含 L20。类型模板不是来自人类数据库的逐帧 retarget
GraspADMM: Improving Dexterous Grasp Synthesis via ADMM Optimization
Ruan / Chen / Wang / Chen，2026-03 预印本		在 Dexonomy 中用 ADMM 改善 hand-pose optimization，交替处理物体接触与可实现的手接触官方实现与变更列表已公开，含 op=grasp_admm。与我们接触优化直接相关，列为 O-ADMM 下一条；不是替换旧 planner 一行配置即可复现
DexEvolve: Evolutionary Optimization for Robust and Diverse Dexterous Grasp Synthesis
Zurbrügg / Cramariuc / Hutter，RSS 2026		分析种子 + 无梯度进化 + 物理仿真选择，多样性与稳定性同时考察官方代码依赖 Isaac Lab / Isaac Sim 栈。适合“数学分数好但模拟差／候选单一”时追加；不是本地 MuJoCo 即插即用替代

选型顺序的依据是项目成本，不是宣称绝对性能排名：旧 BODex 已有运行链 → 类型与接触问题看 Dexonomy / GraspADMM → 需要动力学筛选与多样性再看 DexEvolve。SpringGrasp 针对柔顺／形状不确定，FRoGGeR 是分析质量与 refinement 的参照。不同论文的“鲁棒”可能仅指解析 wrench 指标、六向重力、开环抬起或特定扰动，不能互换。

§ 7统一候选合同：让来源可替换、后续管线不重写

以下是未来接入多种来源时的接口备忘，不是当前待办，也不是本仓库新增代码。生成与优化产物归 grasping，环境／controller 归 human_machine_interaction；只读导入已经冻结的 candidate bank。

每个候选不只保存一串关节角；缺字段时标 invalid，不猜
字段组必须保存验收用途
来源candidate_id、source_route(H/G/O 可多选)、dataset / subject / sequence / frame、method / commit / checkpoint、seed、license、parent_candidate_id区分人工与真实人类；追踪 retarget / refinement，按来源分组切分
本体与对象right L20、hand_model_hash、object_mesh_hash、collision_hash、尺度、质量／惯量、单位、joint_names、coupling_versionORCA / Allegro 与 L20 不混用；同名物体不同 mesh 不冒充配对
抓姿palm frame 定义；T_OP（palm 在 object frame 的位姿）；q_pre、q_grasp、q_hold；16 主动关节、rad；四元数顺序q_grasp 是几何接触姿态；q_hold 是承重控制目标，不能互相默认为同一量。BODex squeeze 必须显式转换
控制与过程position-target / torque 等动作语义、kp / damping / force limits、close / lift 时长、腕部目标路径、限幅与速率版本离线抓姿与实际 actuator ctrl 区分；初始化最终输出还包括完整积分状态

质量与状态IK / joint-limit / penetration / contact 检查、优化预算与耗时、init_attempts、accepted、reject_reason、evidence 路径、protocol_version、split不丢失败候选；q_ref=q_hold 只有通过固定 PD 承重后才能冻结为 controller reference

坐标语义：T_OP 用于离线 object-centric 来源；持物 reward 使用 T_PO=T_OP⁻¹。在验收记录中用一个已知变换的测试验证 round trip、四元数与单位，不靠变量名猜。欠驱动 L20 由同一耦合定义恢复被动关节，输出 16 个主动目标不是忽略 5 组耦合。

两个实验轴，不做一次混乱的大混合

  1. 来源质量表：固定 L20、对象、控制器与初始化预算，比较 H-vector / H-DexPilot / O-BODex 等。报告生成可行率、承重通过率、固定 PD 的条件稳定率、每个原始候选的整体成功率、style 合规和生成成本。
  2. 持物控制表：固定一份来源明确的合格初态 bank，在完全相同 scenario 上比较 B0 / B1 / B2 / B3。不能让 PPO 用优选 grasp 而 PD 用原始失败 grasp。

真正比较多种来源时，再根据实际资源确定候选数、预算和测试划分；届时记录全部失败与人工编辑，不把文献库里的备选自动升级为实验要求。

若比较“直接 retarget”和“retarget + optimizer”，保留为两列；纯自动方法不能只挑最漂亮视频与人工反复修好的一个模板比赛。跨方法场景与预算统一，但各自合格初态不同，因此来源表不是 controller 能力归因。

§ 8如何使用这份文献库

当前先执行Stage 1.1 数采，之后在Stage 1.2 Training并列测试 No-Gaze VQ-VAE＋自回归 Transformer 与 Flow Matching，并保留确定性回归基线。这里的数据库、retarget、优化器和其他生成模型是来源备选，不预排移植顺序；有实际需求后再选方法。

对 SOTA / “大家常用”的结论：没有可核验的统一使用量统计，不能诚实地选出“行业用得最多的一篇”。更可操作的工程参照是：dex-retargeting 有独立库与视频／HOI 示例；DexGraspNet 系列提供被后续方法使用的数据与比较基准；BODex / DexGraspBench / Dexonomy 有连续的合成、评测与类型扩展链。它们属于可复用的基础参照，不是因较老就过时，也不是因有代码就已成熟适配 L20。

近期变化不是一律“训练一个再蒸馏”：还有不训练的优化、接触／类型条件生成、跨本体表示、物理轨迹 retarget 和进化筛选。后续可通过 candidate / controller 边界复用这些方法，最终服务于符合用户选择的局部 pick/hold 策略；当前 PoC 不要求接齐这些模块，是否引入 VLA 是长程调度层的独立决定。
